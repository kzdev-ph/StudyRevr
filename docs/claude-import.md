# Lessons written by Claude (lesson:export / lesson:import)

Moved verbatim from CLAUDE.md (full original: docs/CLAUDE-full.md). CLAUDE.md keeps the short rules; this file has the detail.

- **Lessons written by Claude** (`npm run lesson:export -- <lesson id> <folder>` / `npm run lesson:import -- <folder> [--as-new] [--yes]`, branch `feat/claude-import`; `server/scripts/export-lesson.js`, `import-lesson.js`, `server/src/services/claude-exchange.js`, `server/src/ai/file-ai.js`): an offline path where Claude Code (Haiku agents) writes a lesson's content instead of the Default AI and the app imports it through **the same pipeline**: `runPipeline` itself runs, with a file-backed `ai` whose `generateJSON` reads `replies/<name>.json` instead of calling a provider, so the same zod schemas and every code check apply (evidence quotes in `raw_text`, leak rules a-m/o, list-sibling shape, `REWORDED`, objective blocks, related terms, blank options, the quick-check grounding and both AI reviews with their fix rounds). Nothing is reimplemented, so a check added later applies to imports too. **Live taps (Explain simpler, Filipino/Taglish) and Prepare stay on the Default AI / student key / Gemma**; only lesson content can come from Claude, and an import writes no section versions.
  - **Rounds, because prompts depend on replies.** The key-points prompt contains the generated sections, flashcards take the sections and key terms, wrong options take the cards, the review takes everything, and the fix rounds depend on what is flagged, so all prompts cannot exist up front. `lesson:export` is run again and again: each run replays the replies already in the folder through the real pipeline in a **scratch in-memory database** (the real database is only read, on the first run, and may be in use by a running server), then writes every prompt that is now waiting: `prompts/NN-<name>.md` (system message, user message, the expected JSON Schema, the reply file) and `.json`, `NEXT.txt` (what is waiting, replies that are unusable and why, and **what the checks dropped or asked for again**), `lesson.json` (the lesson, plus the summary length, card cap, chunk size and key-term cap its prompts depend on), `raw_text.txt`, `blocks.json` (the slide / page structure) and `INSTRUCTIONS.md`. It says COMPLETE when nothing is waiting. Expect 8-12 rounds for a small lesson (sections, key points, key terms, flashcards, list items if room is left, wrong options and their second try, then the review, its fix rounds and round 2). A relative folder is from where you typed the command.
  - **A reply that cannot be used never lets the run go on.** A call with no reply, a stale reply or a reply failing its schema (or not JSON) hangs instead of throwing: stages such as the quick-check second try and the review fix rounds catch a failed call and carry on without the item, which would quietly build a different lesson. The export reports it instead (`Fix these replies`). Calls are named by their label (`the review sections`, `the quiz answer options (second try)`; a repeat gets `-2`) and a reply is tied to the hash of the prompt it answers (`manifest.json`): when an earlier reply changes what a later prompt says, the later reply moves to `stale/` and is asked for again; a reply for a prompt that was never exported is ignored. Replies may be wrapped in a code fence.
  - **Import.** First the whole folder is run in a scratch database (nothing waiting, nothing failing, or it refuses and prints what is missing), then the same run on the real database inside **one transaction** that is rolled back unless the lesson comes out `ready` with a `done` job, so a refused or failed import leaves the database as it was. The two settings the prompts depend on (`summary_length`, `flashcards_max`) come from the export for the run and the real values are put back. `--as-new` makes a separate lesson (origin `admin`, no owner, not shared, title + " (Claude)", the same text and source numbers; a student's upload copied this way becomes a teacher's lesson everyone sees, so copy only your own test data). Without it the exported lesson is replaced in place under **`lesson:rebuild`'s rules** (`checkRebuild` / `resetLesson`: refused while it is processing or when a participant other than P00 has records, you type the lesson id unless `--yes`; refused too when its text changed since the export). Both refuse while a server runs (`serverBlock` in `services/server-check.js`, shared with `lesson:rebuild`). The import report lists what the code checks dropped.
  - **Provenance:** `lessons.made_by` (migration 017): `gemini` (default: the pipeline with the admin Default AI, also every lesson made before the column existed, whatever provider was set) | `claude-haiku` (an import) | `mixed` (a `claude-haiku` lesson later changed by the Default AI: Regenerate this card, Review again, Remake quiz answers, Make cards, a retry, or the quiz-start fallback that fills in missing wrong answers; marked when that work starts, so it can over-claim a change when the work then fails but never hides one, `markMixedIfClaude` in `server/src/services/lesson-author.js`). Shown to admin ("Written by Claude (Haiku), imported" in the lesson row and preview, a note for `mixed`, never to a student), exported as `made_by` in `lessons.csv` and explained in the codebook; importing again sets `claude-haiku` and `lesson:rebuild` sets it back to `gemini`. An import runs as Minimal thinking and leaves `thinking_level` NULL.
  - **The writer's own prompts** (`server/src/ai/prompts-haiku.js`, feat/study-prep): `runExchange` passes every request through `haikuRequest` before the file-backed AI hashes it, so the exported prompts, `manifest.json` and the replies are for the Haiku text, and nothing else in the app imports it (the Default AI and Gemma keep `ai/prompts.js` unchanged; `test/prompts-haiku.test.js` checks both). It is the shared prompt plus exact swaps and added lines (each throws when its anchor is gone), found by `promptKind` from the system message: every content prompt gets "read the whole lesson first, cover every detail (list items, definitions, examples, numbers), only what it says, plain words for Grade 11, no padding"; a quote is the line that states the answer, never a heading or a line ending in ":" (lesson 32 #744); never "What does X ask?" (a lesson item written as a question is asked as what it is about or looks at, #751 #753 #754 #756); a bare list item is split (verb in the question), never described by synonyms, and a "Name — what it means" line is asked for its description; key-term definitions start with what the lesson says about the term (no "A type of…"), and the lesson's overall topic is left out when the other terms are its kinds; the wrong-answer prompt gets the whole lesson (`<lesson_text>`, which the shared one never sees) and asks for options built from the lesson's ideas about other things, fitting the question's grammar, never also right, never a synonym or broader name, never another card's exact answer (rule f still drops it), believable as a Yes/No statement, and never reused across cards (#729 "Exam questions."); the quiz review flags an option the same way on every card of the batch where it is also right, a broader term on every card it covers (lesson 32 #755 missed the flags its siblings had), a `yes_no` statement a student who knows the lesson would say Yes to as `two_correct`, a plainly off-subject option as `giveaway`, and "What does X ask?" as `vague`. No code check is changed. `INSTRUCTIONS.md` says the same in short. Added during the test run: a split list item quotes the line that introduces its list together with the item line (the item line alone, "Test hypotheses", has one explaining word and the evidence check drops it); the flashcard prompt asks for the number of concept cards the pipeline really keeps (`flashcards_max` minus the term cards, passed by the exchange as `maxCards`; the shared prompt's larger number let the cut drop the last slides), calls it a hard limit, asks to spread the cards so every slide keeps one, and one question per card; an item the lesson writes as a question keeps its description as the answer with a person doing the asking ("When choosing a delivery service, what do customers ask about response time?" -> "How fast the service replies"; asking for the name instead would contradict the "Name — what it means" rule, whose sibling names are other cards' answers that rule f drops); the review flags a term option and the same term's definition as a Yes/No statement together; the examples are made up, none from a lesson we test on. **Measured** (RSCH2120, 2026-10-18, on a database copy; lesson 32 = Haiku with the shared prompts, lesson 38 = one Haiku agent (writer and reviewer) with these prompts, imported `--as-new`; n = 1): `quiz:check` 32 / 38: multiple choice clean 21 of 28 / 30 of 30, Yes/No false statements clean 72 of 116 / 113 of 141, cards never asked 3 / 0, AI review flagged 13 / 5 cards, quick checks 12 / 18 (none dropped), clean questions 10 of 10 on both, no wrong-answer reused on two cards in either. A separate Opus grader, blind (both lessons' 430 items shuffled, labels hidden), with a 52-item coverage checklist and the rule fixed before grading (3·High + 2·Medium + 1·Low per asked quiz form; better = lower per form, coverage not lower, no new High): no High issue in either; per asked form 32 = 0.195 (23 / 118), 38 = 0.145 (25 / 172); coverage in the review 52 / 52 on both, by a card 34 / 52 (32) and 37 / 52 (38): **38 is better under the rule**. 38's issues: 12 awkward forms of "which consideration is about data quality?" answered with the description (from the rewrite round, after the reviewer flagged "what does response rate look at?" as vague; the prompt example now has a person ask, not re-measured), "Decisions" offered for what data helps researchers draw (arguable two correct, 2 forms), the Self-Report card's Yes/No statements "collected through phone calls" / "face-to-face" (2 forms, the review flagged the terms but not their definitions; now in the review prompt, not re-measured), 5 weak Yes/No statements, one giveaway set. 32's: 13 forms of "what does X ask", Longitudinal / Panel crossed (4), the header quote (#744), "Exam / Classroom questions", 3 padded sections. Hand steps in the run: hints on the quick-check second try (quote the four item lines) and on which list groups to cover; the writer was sent back once to drop two key terms (a broader term and one named by its definition) before that rule was in the prompt, and given the hint for the rewrite wording that produced the 12 awkward forms; every review flag was checked against the lesson and none was deleted. Card coverage stays below the lesson's 52 details because `flashcards_max` (30) is the limit: raising it is the lever for full coverage.
  - **Reviewing the writer**: the review prompts (`the quiz review`, `the quick check review`) are the pipeline's own strict-reviewer prompts; for the experiment a second agent answers them and every flag is checked by hand against the lesson before the next round (a wrong flag is deleted from the reply file, since the import will act on it). Prefer a different agent for the review than for the writing.
  - **Measured** (RSCH2120 Data Collection Methods pptx, 2026-10-17; lesson 31 = the Default AI (Gemini, Low thinking), lesson 32 = written by one Haiku agent and reviewed by a second, every flag checked by hand, imported `--as-new`; n = 1 run each, not a benchmark): `quiz:check` 31 / 32: flashcards 26 / 30, multiple choice clean 12 of 22 / 21 of 28, Yes/No false statements clean 36 of 78 / 72 of 116, cards the quiz never asks 7 / 3, AI review flagged 12 of 26 / 14 of 30 cards, quick checks 9 / 12 (none dropped), clean questions 10 of 10 on both. The same strict-reviewer rubric as `fix/quiz-wording` (awkward, position, objectives, nested, confusing, guessable, two right answers) run blind (labels A/B, one Haiku agent, per question form as a student would see it): Claude version 29 of 94 forms with a problem (awkward 16, guessable 10, two right 3, nested 1, confusing 0, position 0, objectives 0), Gemini version 31 of 55 (awkward 24, two right 8, confusing 5, nested 4, guessable 3, position 0, objectives 0). Hand check of the flags: the Gemini set's awkward / guessable forms are mostly the open `regarding <synonym of the answer>` tails ("regarding suppositions" for hypotheses, "regarding choices" for decisions: rule m catches only a tail that repeats the answer's words) and broader/narrower term pairs; the Claude set's are "what does a survey method's response rate ask?" (an "ask" with no one asking: 12 forms from 3 cards), a definition blanked twice into a fragment, weak absurd options in two cards, and "Data Collection" offered against "Case-Control Studies". Two of the Claude set's `two_right` flags are arguable ("Interviews and questionnaires" under online surveys; "Information collected directly from participants" for Case-Control). Counts are per form, so a card asked in several forms counts several times, and the two sets differ in size (94 and 55). **The judge is not independent**: the reviewer agent was the same one that reviewed the Claude version during the import, and the original `fix/quiz-wording` rubric text was not in the repository, so the categories above are defined from their names. Findings about the pipeline, not the writer: the writer's list-item cards were dropped by "evidence is only the term or a title" (10 cards, so the list-item coverage call never ran at the 30-card cap); the reviewer over-flags a broader term against its narrower one ("Data Collection" for every method) and missed Panel against Longitudinal; only 1 of 3 flagged cards could be rewritten (the new quote failed the quote check); round 2 left 4 items still flagged, which the quiz leaves out.
