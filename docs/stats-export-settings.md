# Stats, research export, Settings

Moved verbatim from CLAUDE.md (full original: docs/CLAUDE-full.md). CLAUDE.md keeps the short rules; this file has the detail.

### Stats
- Per participant (`GET /api/stats`, `server/src/stats/participant.js`); `StatsScreen.jsx` and `StatsView.jsx` are lazy-loaded. Written as a page of notes: no cards or tiles.
- Study time this week: a sentence with the total (highlighted), the three parts as a legend line, then one ruled line per day Mon–Sun (the day in the margin, a bar in the activity colours scaled to the busiest day, inked in from the left once per Stats open (scaleX, 40 ms apart, a tap finishes it), the time written at the end; segments come from `daySegments` in `lib/stats.js`, which leaves out a zero, so no stray "0" is rendered), "Most active day", and a "Show as a table" view.
- Flashcards: reviewed this week, % Good or Easy this week, due tomorrow (cards whose `due_at` falls in the next study day), each written large in the margin with its meaning beside it, then an all-time line. A missing percentage is a dash for the eye and "No answers yet" for a screen reader.
- Quiz scores: first and best finished score per lesson (abandoned attempts not counted): the best in the margin, the lesson title as an `<h3>`, a thin track per score.
- Chart colours are the `--series-reading` (navy / pale blue; AMA's is #3548a8, apart from its accent #2A367D, and inside the dataviz lightness band), `--series-flashcards` (orange) and `--series-quiz` (teal) tokens in `tokens.css`, spread in lightness for colour-blind readers, and the quiz is also striped (`.swatch--quiz`, `data-activity="quiz"` in `stats.css`), so no series relies on colour alone, for study time; every value is also written out (legend, day lines, table). The quiz-score bars do not reuse those (they would mean two things on one screen): Best is `--accent` (`--score-best`: `--ink` in the AMA themes, so the line never reuses a series colour), First try is `--ink-2`, and a lesson with one finished quiz shows a single "Score" bar.
- Flashcard done card recap: cards studied this sitting, active time, % Good/Easy (undone answers removed; `sessionRecap` in `lib/flashcards.js`).

### Research export (admin only)
- `GET /api/admin/export.zip` (all files + `README.txt` codebook) and `GET /api/admin/export/<file>.csv`; `?include_p00=1` includes P00 (left out by default). UTF-8 with BOM, CRLF, text starting with `= + - @` prefixed with `'`. Only study tables are read, never `settings`: no names, settings, keys or PIN.
- Files: `summary` (main measures: the teacher's lessons only; each has an `_all` twin that counts every lesson), `lessons` (origin, shared, owner), `lesson_events` (uploads, failures, deletes, shares), `sessions`, `flashcard_reviews` (with due_date / due_status / days_late), `due_reviews` (planning: on_time / late / still_overdue), `quiz_attempts` (status finished / abandoned / open, `is_retake`, `retake_of`, `is_first_attempt`), `quiz_answers` (a term card's definition in `question` / `statement` is stored as shown, with the term masked as `___`; the codebook says so), `events`, `setting_events` (`setting`, `value`, `study_date`; a participant's Motion choice changes), `ai_calls` (live rewrite requests: `kind`, `outcome`, `ai_source` student / default / gemma, `ai_provider`, `ai_model`, `ai_fallback_steps` (see Live calls), `ai_fallback_reasons` (the codebook lists every reason: rate_limit, timeout, network, provider_error, auth, no_credit, not_found, bad_request, invalid_json, bad_response, not_configured, error), `from_cache`, `saved_shared`, `error_code`, `ms`; rows without a participant are left out). Never `participant_ai_keys`.
- `summary.csv`, one row per participant, columns grouped by SDL dimension: `planning_days_active, planning_total_sessions, planning_reading_min, planning_flashcards_min, planning_quiz_min, planning_total_min, planning_first_study_date, planning_last_study_date, planning_reviews_on_time, planning_reviews_late, planning_reviews_still_overdue, planning_avg_days_late, planning_on_time_rate` (= on_time / (on_time + late + still_overdue)); `retention_cards_reviewed, retention_good_easy_pct, retention_quiz_first_pct_mean, retention_quiz_first_pct_L<lesson id>`…; `self_monitoring_stats_views, self_monitoring_quiz_retakes, self_monitoring_review_flashcards_taps, self_monitoring_simplify_taps, self_monitoring_translate_taps`. Days active = study days with active session time, a flashcard answer or a quiz answer; total sessions = sessions with active time.

### Settings (gear icon)
- AI provider: presets (Google Gemini (default), NVIDIA NIM, OpenRouter, Ollama, llama.cpp, Custom) that prefill base URL; per-provider API key (shown only as set / not set); model picker fed by `GET /api/settings/models` with a free-text fallback; "Test connection" tests the provider + model in the form before saving
- Quiz question count; flashcards per lesson; summary length (short / detailed); include speaker notes (`include_speaker_notes`, default on; applies to pptx uploads made after changing it)
- Flashcard: new cards/day, max reviews/day, learning steps
- Data: delete lesson, reset flashcard progress, export/import JSON backup
- Appearance: theme (Match my device / Light / Dark / AMA / AMA Dark; `client/src/lib/theme.js`, localStorage `studyrevr-theme`, written to `data-theme` on `<html>`, and applied before the first paint by a small inline script in `client/index.html` (theme and motion, the same rules; `client/test/theme.test.js` keeps them in step); a device with no saved choice gets **AMA**, and Match my device is stored explicitly as `system` so it stays distinct from "never chose" and still follows the device between Light and Dark; AMA and AMA Dark also set a `theme-color` meta for the status bar) and **Motion** (Match my device / Less motion / Full motion), the same segmented control; both are kept on the device (localStorage).
- Built in Phase 6: "Participant P03 · Switch participant" (the "Researcher admin" link moved to the code screen)
- Built in Phase 7A (`MyAiSettings.jsx`, shown only while admin allows own keys, or to remove a key saved earlier): "AI for Explain simpler and Filipino/Taglish": **Default** (the admin's key and model) or **Use your own key** (provider Google, DeepSeek, Qwen, NVIDIA NIM or OpenRouter (`STUDENT_PROVIDERS`, fixed base URLs), a pasted key with the warning "Your key is stored on the study laptop. Only use a key you can delete later.", a model from the filtered list via **Show models**). **Test key** (`POST /api/my-ai/key`) sends `testConnection` live and saves only on success ("Connected. [model] is ready."); failures: "The key was rejected. Check that you copied all of it." (auth) / "The key works but has no credit or quota left." (402, or a 429 naming a per-day quota, `limit: 0`, credit or balance) / "Too many requests right now. Try again in a minute." / "This model isn’t available with your key." (404, 400) / "Couldn’t reach [provider]. Check the internet connection." (network, timeout) / "[provider] had a problem on its side. Try again in a minute." (5xx) / "This model didn’t answer in the expected format. Pick another model." (invalid JSON). **Remove my key** (`DELETE /api/my-ai/key`) returns to Default. The key is shown only as its last 4 characters.
