### Admin (Phase 6)
- `#/admin`, reached from a quiet link under the card on the code screen (not from Settings: students don't need it). Phase 7A sections after Research export: **AI and study settings** (Default AI: provider, key set / not set, chat-model picker with free text when the list fails, Test connection, Save; New flashcards per day; switch "Allow students to use their own API key", default off; **Think harder when preparing lessons** (Minimal / Low / Medium / High, default Low, see Thinking for lesson processing); **Delete all student keys** with a confirmation, `DELETE /api/admin/student-keys`, for after the study; above the form, a warning for each Default problem settings can fix seen in the last 24 hours — model not found, key rejected, no credit, bad request, not set up — with how many requests the backup AI answered and how many got "try again": `GET /api/admin/ai-problems`, `server/src/services/ai-problems.js`, read from `ai_calls`) and **Backup** ("Download backup", "Last backup: …"). `ADMIN_PIN` in `.env` (empty: admin off, 403 `admin_off` everywhere). The client sends `X-Admin-Pin` (kept in sessionStorage after `POST /api/admin/unlock` accepts it) **only on calls flagged `{ admin: true }` in `client/src/lib/api.js`**, never on a student call: a student request from the same tab carries no PIN, so an unlocked tab cannot see a student's private lesson or act as admin by accident (`client/test/api.test.js` classifies every `api` function and fails on a new one that isn't listed). The PIN is cleared (`lockAdmin()`) on **Switch participant** and whenever the route leaves the admin screens (`isAdminRoute` in `lib/router.js`, an effect in `App.jsx`), so the admin routes ask for it again; the server compares digests in constant time (`server/src/middleware/admin.js`); missing/wrong PIN 401 `admin_pin`; 5 wrong PINs from one address lock it for 60 s (429).
- Behind the PIN: everything under `/api/admin`, plus upload / retry / delete of lessons, `POST /api/lessons/:id/flashcards/generate`, and all of `/api/settings/*`. Section rewrites and the quiz's fallback wrong-answer call stay open (studying).
- Screen: **Participants** (add codes; summary table; a code opens `#/admin/participants/P03`, that participant's StatsView), **Research export**, **Lessons** (upload zone, list with delete; per lesson a **Retry** button with the error text when processing failed, **Make cards** (or Try again) when the flashcards stage has not run or failed, a quiz-answers retry button when that step failed or was never made, and the **Prepare simpler and Taglish** step with its status). Because the PIN is only sent from the admin screens, everything admin needs on a lesson is in this list; a lesson opens in a **read-only preview** at `#/admin/lessons/:id` (`AdminLessonScreen.jsx`: title, who owns it, status and error, sections, key points, key terms; it starts no study session, saves no progress, logs no events and makes no AI call). The Flashcard tab and the processing page have no admin branches: a student sees "Your teacher can make them" / "Your teacher can retry it from admin."
- **Prepare** (`POST /api/lessons/:id/section-versions`, admin; `server/src/services/prepare-versions.js`): an on-demand job stage `section_versions` (`ON_DEMAND_STAGES` in `pipeline/jobs.js`: a job queued there runs only that stage and never fails the lesson) that makes every missing shared Explain simpler / Filipino-Taglish version with the Default through the pipeline client (its 15/min limit, retries, concurrency), saving each as it is made; a retry makes only the rest. `GET /api/lessons` rows carry `section_versions: { missing, total, status, error, progress }`. Taps still log `section_simplify` / `section_translate` events as before.
- **Backup** (`GET /api/admin/backup`, `server/src/services/backup.js`): better-sqlite3 `backup()` into a temp file `backup-tmp-<uuid>.db` next to the database (never the system temp folder; removed in a `finally`, leftovers removed at server start), then on the copy: journal mode DELETE, `secure_delete`, delete `settings` `ai_api_key:*` and all `participant_ai_keys`, VACUUM; sent as `studyrevr-backup-YYYY-MM-DD-HHMM.db` (Asia/Manila) and logged in `admin_events` (`GET /api/admin/backup/last`). The PIN is only in `.env`. **Restore**: `npm run restore -- <file>` (`server/scripts/restore.js`; a relative path is from where you typed it, via `INIT_CWD`): refuses while a server runs (the server writes `<db>.pid` on start and removes it on exit; also pings `/api/health` on `PORT`), checks integrity / StudyRevr tables / no unknown migrations, asks to type `RESTORE`, saves `pre-restore-<time>.db` beside the database (it still holds the keys: the script says to delete it once the restore checks out; a stale pid file message says which file to delete), swaps the file in (removing `-wal`/`-shm`), runs migrations, and prints a reminder to re-enter the API key and check `ADMIN_PIN`. Students see no upload, delete, retry or Make cards ("Cards aren't ready yet").
- **Cards that give their answer away** (admin's list, `GET /api/lessons?counts=1`, rows carry `leaks: { cards }`: cards breaking g, i, j, k, l or m (`CARD_LEAK_RULES`); h is not counted, the quiz blanks the term; `GET /api/admin/lessons/:id/leaks` is `lessonLeakReport` in `server/src/quiz/check.js` (h cards listed apart as `names_term`) plus `can_regenerate` and `regenerate_blocked` (`lesson_has_records` | `lesson_busy` | null)): the admin lesson row says "N flashcards need a rewrite." (they give the answer away or ask by place in a list) with **Show cards** (`LeakyCards.jsx`), each card with the rules in plain words and **Regenerate this card** (`POST /api/admin/flashcards/:id/regenerate`, `server/src/services/regenerate-card.js`): one Default-AI call (`regenerateCardPrompt`) with the card, why it was flagged, the lesson block around its evidence and (concept cards) the other cards' answers; a concept card gets a new question, answer and evidence (checked like generation), a term card a new definition (at least half of its content words must be lesson words). Still leaking, too long, a quote not in the lesson, a definition not from the lesson, or a repeat of another card (`isDuplicate` in `pipeline/flashcards.js`, and no other card with the same answer): 422 `card_not_better`, nothing saved. Otherwise the card is updated **in place** (same id, so old `quiz_answers` rows still point to it; P00's schedule is kept) and its `quiz_distractors` row deleted, so "Make quiz answers" remakes them. Blocked with 409 `lesson_has_records` once a participant other than P00 has records on the lesson (`participantRecords` in `server/src/services/lesson-records.js`, shared with lesson delete); the list then says the cards can't change. Also refused with 409 `lesson_busy` while the lesson is not ready or any job is queued or running on it (processing, quiz answers, Prepare, making cards) (`regenerateBlock`). Both are checked again inside the save transaction after the AI call, together with the card's text (changed meanwhile: 409 `card_changed`), so a participant who started during the call blocks the save.
- **`npm run quiz:check`** (`server/scripts/quiz-check.js`; `-- --lesson <id>`, `-- --db <file>`, a relative path from where you typed it): opens the database read-only (safe beside a running server; works on any StudyRevr database), no AI or key, and prints per lesson the flashcards flagged by g-m (and `o`, a card made from the learning objectives, which the quiz skips), the multiple-choice questions and Yes/No false statements possible / clean / skipped by rule with up to 5 examples, the term definitions shown blanked, the cards the quiz never asks, the AI review (cards whose review matches what the quiz shows now, how many are not reviewed yet or changed since, the key-term families and up to 5 flagged cards with why; skipped options say `ai` or `r`, a related term), and **"Clean questions available: N of 10"** (run it before the study to confirm the study lesson fills a full quiz).
- **`npm run lesson:rebuild -- <lesson id>`** (`server/scripts/rebuild-lesson.js`, `server/src/services/rebuild-lesson.js`): makes a lesson again from its stored `raw_text` with the current prompts and checks (the original file is not stored, so a lesson made without a file in `test-lessons/` can be rebuilt too). It **keeps the same lesson id and its title, file name, origin, owner, sharing and source numbers** (so `lesson_events` and the exports still point at it), and in one transaction deletes its sections, key points, key terms, flashcards (and their progress, answers, wrong options and reviews), quiz attempts and jobs together with P00's sessions and events on it, then runs the whole pipeline with the admin Default AI (about 10-20 calls, thinking level from the setting). It refuses (`RebuildRefused`) while a server runs (pid file or `/api/health`), while the lesson is processing, and when a participant other than P00 has any flashcard answer, quiz attempt or answer, session, event or reading position on it; it asks you to **type the lesson id** to go on. Used on lessons 25-31 after the quiz-wording fixes.

- **Lesson delete is blocked** (409 `lesson_has_records`, `records` counts in the body) once a participant other than P00 has flashcard answers, quiz attempts/answers, study sessions or events on the lesson. The message says what deleting would do: remove their flashcard answers and quiz attempts (with answers), and cut their sessions and events off from the lesson (those rows stay, `lesson_id` goes NULL). P00 records do not count and go with the lesson. There is no override: a lesson becomes deletable only when those records are gone.
