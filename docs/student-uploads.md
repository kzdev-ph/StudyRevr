# Student uploads (Phase 7B)

Moved verbatim from CLAUDE.md (full original: docs/CLAUDE-full.md). CLAUDE.md keeps the short rules; this file has the detail.

### Student uploads (Phase 7B)
- **Off by default** (admin: "Allow students to upload lessons", `allow_student_uploads`, with "Uploads per student per study day", `student_uploads_per_day`, default 2, 0-20), so the study runs on the teacher's lesson unless the researcher turns it on. Both are in the AI and study settings; every changed setting is logged in `admin_events` (`setting_changed`, `key=value`). Turning the switch off only hides the Upload button: lessons already uploaded, and their records, stay and their owners keep studying them.
- **A lesson has an origin**: `admin` (the teacher's, everyone's) or `student` (an upload). Visibility is one rule, `visibleSql` / `visibleLesson` in `server/src/services/lesson-access.js`: `origin = 'admin' OR shared_at IS NOT NULL OR owner_participant_id = me`; admin (a valid PIN) sees all. It fails closed: a private upload whose owner is gone is visible to nobody. **Another student's private lesson answers 404 "Lesson not found." (never 403), the same as a lesson that doesn't exist**, on every route that reaches a lesson, directly or through a card, section, review, attempt, session or event: lesson routes, `/sections/:id/*`, `/flashcards/*` (decks, due, the All lessons deck and its new-card budget, review, undo), `/quiz*`, `POST /sessions`, `POST /events`. A wrong PIN on these routes counts toward the PIN lockout (`requireAdmin.isAdmin`), so they are no oracle for guessing it. `test/lesson-access.test.js` calls every route as owner / other student / admin / no headers / another student after sharing, and a coverage test reads the live router stack (`app.router.stack`; every router is mounted through `mount()` in `app.js`, which tags its prefix) and fails if any route outside `/admin` and `/settings` is not in its tables (shown to fail on a fake unguarded route), while every route under those two refuses a request with no PIN. Students never see an owner's code: their rows carry `mine` / `shared` only; admin's rows carry `owner_code`.
- **Upload** (`POST /api/lessons` without the PIN; with the PIN it is the teacher's upload as before): participant required → switch (403 `student_uploads_off`) → burst limit, 6 requests per participant per 10 minutes, in memory (429 `upload_rate_limited`) → today's quota (429 `upload_quota`; counted from `lesson_uploaded` events per study day, so **deleting a lesson never gives an upload back**, and it is checked again inside the insert transaction) → queue guard (429 `upload_busy` while 5 student lessons are waiting or running) → one upload in flight per participant (409; the slot is given back when the upload ends and when the connection closes, so an aborted request frees it) → a `Content-Length` over the limit plus 64 KB is refused at once with 413 `too_large` (`Connection: close`, nothing read, logged for a student) → multer (same 20 MB limit; one file and a title only: `fields` 2, `parts` 3, `fieldSize` 1 KB, `headerPairs` 20) → file checked **by content**: extension, MIME, signature (`PK` / `%PDF`) and, for docx / pptx, the part that makes it a Word or PowerPoint file (`word/document.xml` / `ppt/presentation.xml`, `assertDocumentPart`; applies to the teacher's uploads too) → text extracted. A file with no readable text is refused up front (422 `no_text`) without using an upload. A file whose text looks poor is still accepted: the code (`scanned_pdf`, `damaged_text` or `short_text`) is stored in `lessons.text_warning` and its message is sent in the reply's `warning` and in `text_warning` on the lesson row, to admin and the owner only (another student never gets the key, after Share too). A docx / pptx zip is checked twice: `assertSafeZip` reads the central directory (entry count, declared sizes), and because those sizes are only claims `assertEntrySizes` inflates each entry through a stream that stops at its declared size, so a zip that lies about its size is refused as corrupted before anything is parsed (`server/src/services/zipguard.js`). A PDF has a time budget (60 s, `extractPdf` `budgetMs`) checked between pages; it is **best effort**: pdf.js works in this thread, so a single page that never returns can't be interrupted. The queue limit is checked again inside the insert transaction (and in a student's retry), so uploads that pass the first check together can't push it over. **The original file is never stored** (multer memory storage): only the extracted `raw_text` is kept, so a lesson can't be re-extracted later, there is no file to delete, and a backup is the database alone.
- **Processing**: the same pipeline as the teacher's lessons (sections, key points, key terms, flashcards, quiz answers, the leak rules), with the admin **Default** model only: never the student's own key, never Gemma. There is no automatic Prepare (simpler / Taglish are made on tap, as for any lesson). One processing job runs at a time across the server (the runner chains jobs), in upload order, the teacher's and the students' together. Live student calls (Explain simpler, Taglish) go ahead of queued processing calls in the rate limiter, which keeps 20% of the per-minute slots (3 of Google's 15) for them (`server/src/ai/ratelimit.js`), so processing runs at 12 requests/min instead of 15.
- **Failures**: a student sees the plain "The AI couldn’t prepare this lesson right now. Try again in a few minutes." unless the problem is the file itself (`lessons.error_kind = 'content'`, e.g. no text), never a provider message; admin sees the real error. A student can **Try again** on their own failed upload (`POST /api/lessons/:id/retry`), which does not use an upload (but waits like an upload when the queue is full: 429 `upload_busy`). Known and accepted: a student can still retry their own failed upload while uploads are switched off (the lesson already exists and the retry is free), and processing can starve if live taps stay above about 12 a minute (processing gets 12 of the 15 requests a minute, live calls go first). A server restart fails the lessons it interrupted and logs `lesson_upload_failed` `processing:interrupted` for each student upload. Older provider messages never reach a student either: the quiz's fallback notice, a failed flashcards job (`/flashcards/decks`) and a failed Prepare (`section_versions.error`) are plain lines (`CARDS_FAILED_MESSAGE`, `PREPARE_FAILED_MESSAGE` in `lesson-access.js`). **A student never receives the file name** (list, lesson, upload response; admin does); the title comes from the file name (cut to 200 characters) and the student sees it on their own lesson.
- **Delete**: a student can delete their own upload only while it is private and **before it has any study record of theirs** (a flashcard answer, or a quiz attempt with at least one answered question, or a reading session with active time above 0; opening Review (a 0 ms session), opening the quiz without answering, and quiz or flashcard time without an answer do not count; `ownerRecords`). Deleting also removes the owner's `events` and `study_sessions` for that lesson in the same transaction (unanswered attempts go with the lesson): left behind they would lose their lesson (`lesson_id` NULL) and be counted in the teacher-only measures of `summary.csv`. The trade-off: a simpler / Taglish tap on a private upload that is then deleted disappears from the `_all` twins too; the `lesson_deleted_by_student` row in `lesson_events` stays. Once it is shared or studied, the delete option is gone (409 `lesson_shared` / `lesson_studied`). Admin's delete keeps its old rule (blocked once any participant other than P00 has records).
- **Share** (`POST /api/lessons/:id/share`, admin): a ready, private student lesson becomes visible to everyone. One way, no undo; the admin row asks first. Logged in `lesson_events` (`lesson_shared`, actor `admin`, participant = the owner) and `admin_events` (`lesson_shared`).
- **Events** go in a new table, **`lesson_events`** (migration 012), not in `events`: `events.type` has a CHECK constraint, so a new type would mean rebuilding that table (same reason as `setting_events`, migration 011). Types: `lesson_uploaded` (detail = file name in the database, the extension only in the export), `lesson_upload_failed` (detail = `too_large` | `wrong_type` | `bad_signature` | `wrong_content` | `unreadable` | `no_text`, or `processing:<stage>`), `lesson_deleted_by_student`, `lesson_shared`. `lesson_id` is a plain integer and the title is copied, so a deleted lesson's events survive. A refused upload (switch off, quota, busy) is not an upload and is not logged.
- **Research export**: `lessons.csv` (origin admin / student, shared, owner code; P00's private uploads left out unless `include_p00`, a shared one stays) and `lesson_events.csv`. **In the exports only, a student's upload is titled `Student upload <lesson_id>`** (`lesson_title` in every file, `title` in lessons.csv, the `L<id>` list in the codebook: `server/src/export/titles.js`) and `lesson_events.detail` of `lesson_uploaded` is only the extension, because the title comes from a file name that can hold a name; the database, admin's screens and the student's own library keep the real title, and the teacher's lessons keep their titles everywhere. In `summary.csv` the main lesson-dependent measures count `origin = 'admin'` lessons only (plus the All lessons deck, which has no single lesson), and each has an `_all` twin right after it that counts every lesson (the teacher's, shared and private uploads); `retention_quiz_first_pct_L<id>` covers the teacher's lessons and shared uploads. `self_monitoring_stats_views` has no twin. The codebook says all of this.
- **Withdrawal** (`participant:delete`): the participant's private uploads are deleted with their cards and quizzes; shared uploads stay, lose the owner (`owner_participant_id` NULL, `origin` stays `student`, so the export still reads "student upload, owner withdrawn") and the preview says so. **Backup / restore** carry uploads automatically (they are rows in the database).
- Client (`LibraryScreen.jsx`, `LessonRow.jsx`, `lib/uploads.js`): a compact upload zone with "N uploads left today" only while the switch is on (`GET /api/my-uploads`); own lessons say "Only you see this" / "Yours, shared with everyone", show the preparation stage, and a failed one shows its message with Try again; Delete appears only when the server says `can_delete` and asks in place with an ink button (never red). Admin's row says "Uploaded by P07 · only P07 can see it" and has **Share with everyone**.
