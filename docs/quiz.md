# Mock Quiz

Moved verbatim from CLAUDE.md (full original: docs/CLAUDE-full.md). CLAUDE.md keeps the short rules; this file has the detail.

### Mock Quiz
- Row per lesson: name | Start | best finished score and number of attempts (`GET /api/quiz`). Lessons still preparing, without flashcards, or with only one card say why instead of Start.
- Questions come from the lesson's existing flashcards (no new grounding), built in code when a quiz starts (`server/src/quiz/build.js`, pure, seeded `random` in tests): up to 10 questions, one per card, cards picked at random; fewer if the lesson has fewer usable cards ("This lesson supports 6 questions"). A quiz needs at least 2 cards.
  - **Term card**: multiple choice "which term matches this definition?"; the 3 wrong options are other key terms of the same lesson (term cards, then `key_terms` without a card; plural-insensitive), no AI call. **Never a related term** (`server/src/quiz/related.js`, rule `r` in quiz:check): one whose words are a whole-word run inside the other's ("Self-Introduction" / "Written Self-Introduction") or that the AI review put in one family (`lessons.term_families`) is neither a wrong option nor a false statement for the other (both would be right). Families are for synonyms (or a broader and a narrower term whose names don't show it): `usableFamilies` drops a group that holds a term with its own kinds or only kinds of one thing (all ending in the same word), on save and on read, so siblings ("Written" / "Oral Self-Introduction") stay wrong options for each other. Fewer than 3 other terms: true / false against **another term card's definition only** (never a concept card's answer, which is plainly not a definition); with no other term card the card is not asked. A definition that holds its own term (or a form of it) is shown with the term blanked as `___` (`maskTerm`, which blanks every form `termInText` finds: a word of the term, a form of it (`sameForm`) or a shorter word it starts with ("observing" under "Observational", `inTerm`), never a longer word that holds one, so "databases" stays under "Archival Data" (lesson 32 card #742 was shown as "___ taken from existing records or ___."; Gemini audit 2026-10-18; cherry-picked to feat/study-prep with 2e9ac20, the Taglish key-terms line; d0d5662 was not taken); the same match decides whether the blanked text still shows the term and rules d / e); the blanked text is checked again and a definition that still shows its term is neither asked nor used as another term's false statement; **a blanked definition is never another term's Yes/No false statement** (under "Does this describe Oral Self-Introduction?" the gap reads as a misprint and points at No), so **a term card whose definition is shown blanked gets no Yes/No form at all** (the gap only in the true statement points at it): it stays multiple choice, or is not asked; the stored `answer_text` and the card are unchanged.
  - **List-item card** (a concept card whose answer is exactly an item of a list in the lesson: a `- ` or numbered line on one slide or page with 3 or more such lines, before `Notes:`; case, spaces and a closing full stop ignored; `server/src/quiz/list-items.js`): the wrong options and false statements are the **other items of that list**, chosen in code like a term card's (the first 3 that pass the set checks, and only items of the answer's **shape** (`sameShape`: both names like "Authentic Tone" or both phrases / sentences, and the word counts within twice plus three of each other, judged on the list's own item), written with the answer's closing full stop or none (the AI writes an answer with one, a lesson's list line often has none, so the stop alone would mark the right option), no AI call; a line ending in ":" ("It reduces the risk of:") ends the list before it and starts a new list after it, so a sub-list is never a sibling of the main list; objective blocks are not lists; the wrong-answers stage skips these cards and the review's fix round has nothing to remake for them. Those items are other cards' answers too, which is accepted here (rule f's "another card's answer" is waived for them), as for term cards: they don't answer this question.
  - **Concept card**: multiple choice with 3 AI-made wrong answers. Without 3 clean ones: true / false, whose false statement is one of the card's own saved wrong answers that passes the checks or, with none saved, another concept card's answer on the same subject (sharing a content word with the question).
  - **Leak checks** (`server/src/quiz/leaks.js`, pure, English and Filipino/Taglish: stopwords of both, a light Filipino stemmer for the linker, prefixes, `-um-`/`-in-`, reduplication and suffixes, English plurals and -ing/-ed; each text is stemmed by its own language, and a short phrase whose language `language()` can't tell is compared under both stemmers, a match under either counting; the lesson's words for the off-topic check hold both stems of every word and are cached by the lesson text, `lessonWords`): nothing that gives its answer away is asked, and **nothing without text is saved, reviewed or shown** (`hasText` / `hasBlank` in `quiz/build.js`: no letter or digit once whitespace, invisible characters such as a zero-width space, and the `___` gap are taken away; applied to wrong options and false statements when the AI reply is parsed, saved and loaded, to the reviewer's items, to a term whose definition is only its own term, to a built question, and when an attempt starts). Rules: **a** the question holds the answer or 80% of its content words (a one-word answer only as a whole word or stem: "Cell" is not in "excellent", "Data" not in "database"; a form of a word is the word: `sameForm`, "professional" / "professionalism", "create" / "creates" / "creation", a shared base of at least 5 letters plus a common ending, or of at least 4 for the plain inflections `-s -es -d -ed -ing`: "formed" / "form", "reviewed" / "review"; "state" / "statement", "form" / "formal" and "data" / "database" stay apart; also in rules b and h; a 2-word answer with one word echoed, like "Form hypothesis" under "What is formed…", is still under rule g's 80% and is not flagged); **b** two or more words of the question that only the right option repeats, as the same word or stem ("data" is not "database"), leaving out the question's topic (its word the lesson uses most, such as `wika` or "plants"), so one echoed word never flags; **c** the right option stands out (length outside 0.6-1.6x and more than 4 words apart, the only full sentence, every wrong option opens with the same 2 words, or tone: the wrong ones are negative or reversed beside a positive right answer, or the right answer is the only negative one. Negatives are whole words: `hindi`, `wala`, `not`, `never`, English reversing verbs in their inflected forms (`prevent(s/ed/ing)`, `hide(s)`, `hiding`, `remove`, `harm(ful)`...; not `hidden`, `harmony`, `blockchain`, nor `reduce` / `decrease`, which only describe an amount), Filipino reversing stems compared exactly (`pigil`, `tigil`, `bura`, `hadlang`, `wala`...; not `burador`), and `mahirapan`, `alisin`, `itago` only in those verb forms (`paghihirap`, `pag-alis`, `nakatago` are topic words); `bawas` no longer counts; "No. 7" / "(no.)" is the number sign); **d** a term question's definition holds the term; **e** a Yes/No false statement that is false from its wording (negative, another language, another kind of card's answer, another subject, another concept card's answer when it is a saved wrong answer) or that is the right answer's own words (reworded, so maybe true, or reversed); a term question's false statements (other term cards' definitions) also go through it, and never name the asked term; **f** wrong options that are near-duplicates of each other (content-word overlap 0.7 or more), the right answer's own words (a second right answer, or a swapped / reversed copy), another concept card's answer (it plainly answers that other question, so a student matches it away), in another language, or about nothing in the lesson; **and, for a concept card's own saved wrong answers (not list siblings, not another card's answer, not Filipino, not two enumerations of 4 or more items), an option sharing `REWORDED` = 0.36 of its content words with the right answer, which is the same claim reworded (a second right answer): this is also rule e for such an option used as a false statement.** The 0.36 threshold was measured before it was kept (lessons 25-31 plus three fresh runs of Self-Introductions, Nature of Inquiry and RSCH2120 that the threshold was not tuned on): it dropped options only in lesson 27 (44 of 107, every one a reworded right answer: "used to promote a local service or event" for "used to advertise a product, service, or event"), nothing in the fresh runs, and one legitimate option in lesson 28 (the same list of five with one item swapped), which the enumeration exemption now keeps; the Filipino exemption exists because the stemmer cuts "nagkaroon" to "roon", so two options in one sentence frame looked reworded. `quizCandidates` in `build.js` keeps only clean forms per card (multiple choice first, then Yes/No, else the card is skipped), so a lesson that can't fill 10 clean questions gets fewer ("This lesson supports N questions"); `usableCount` (the Mock Quiz tab's number) uses the same filter with the saved wrong answers and the lesson text. These are word checks: a question whose *meaning* gives the answer ("Why is language called dynamic?" -> "it changes"), a wrong option reversed in meaning without a negative word, or a synonym of the right answer ("pagbabahagi" for "share") is left to the prompts and the admin flag.
  - About 3 in 10 questions are true / false (choices `True` / `False`) for variety even when every card could be multiple choice. Multiple-choice options are shuffled silently. **Trailing punctuation never tells options apart** (`normalizeTrailing` in `server/src/quiz/build.js`, found when a Claude-written lesson had "Hypotheses." as the only option ending in a full stop, 11 of its 23 multiple-choice questions, and the code checks did not see it): of the texts shown together (a multiple-choice question's four options; for Yes/No the statement, its sibling false statements and the real answer), when some end in a full stop, a colon or an ellipsis (`…` or `...`) and others don't, that mark is taken off every text that has it, each mark on its own, so a lone ellipsis or colon goes too. Nothing is changed in the card, `quiz_distractors` or the reviews: only the built question is, which `quiz_answers` stores as shown, like a blanked term (`answer_text` follows, so `choices[answer_index]` is still `answer_text` and a true statement is still its `answer_text`; the codebook says so). Left alone when every text agrees, and when taking a mark off would make two different texts equal ("Errors." and "Errors") or leave one with no text. An inner stop ("e.g. surveys") stays. Tests: `server/test/quiz-trailing.test.js` (lesson 33's case). Not retroactive: an attempt started earlier keeps the text it was made with.
- **Wrong answers** (`server/src/quiz/distractors.js`): made as the last step of lesson processing (the pipeline's `quiz_options` stage, after flashcards; the lesson stays `processing` until it ends, so students never wait on the AI when starting a quiz). The AI is asked (existing adapter, rate limiter, zod, one JSON retry) for 3 wrong answers per concept card, in batches of at most 15 cards so each call stays under the 25 s timeout; batches run up to the provider's concurrency. The prompt gets each card's question, answer, evidence quote, word count and language, uses only that lesson content, explains `Notes:`, and asks for wrong answers that directly answer **this** question and are the same kind of thing it asks for (a condition for "Kailan…", a list of the same category for "Anong uri…"), never another card's answer, on the question's subject, similar in length and style to the correct one, **in the same tone and polarity** (no negations, opposites or "hides / prevents / limits" versions; it no longer asks to "reverse a relationship", which made the right answer the only positive option), echoing the question's words when the right answer does. In code, wrong answers that match the correct answer or each other (case-insensitive, trimmed), run over 40 words, or break rule c (tone, length) or f (language, off-topic, the right answer's own words, another card's answer) are dropped, and the 3 kept must pass b / c / f as a set (`pickWrongSet`). A card left without a clean set gets **one** follow-up call (label `the quiz answer options (second try)`) listing the kept answers and the rejected ones with why; whatever is clean then is saved (fewer than 3: the card is asked as Yes/No), and a set still not clean after that call is **settled** (`quiz_distractors.settled = 1`, migration 010): no remake or lesson retry asks the AI for it again (a failed follow-up call does not settle it; regenerating the card deletes the row). Saved in `quiz_distractors` and reused; a batch that fails is not saved. **Failure of this stage does not fail the lesson:** the job records `quiz_options` / `failed` with the message, the lesson is `ready`, and admin gets a retry button (`POST /api/lessons/:id/quiz-options`, also used to fill in lessons made before the stage existed and to remake saved sets that give the answer away; only those cards are asked for). No wrong answers are made for a card that can never be multiple choice (its question gives the answer away, rule a or k). A set is saved only if the card's question and answer are still the ones it was made for (a card regenerated during the call is asked for again). The stage and the retry use `includeFailing` (`cardsNeedingDistractors`): cards with no saved row plus cards whose saved set the quiz can't use (not cards whose own question gives the answer away, nor settled sets), so the stage converges. Admin's list (`GET /api/lessons?counts=1`) rows carry `quiz_options.missing` (none saved) and `quiz_options.weak` (saved but leaking, not settled, and the card's own question doesn't give the answer: what a remake can still fix; the admin row then says "N quiz questions are skipped or changed to keep answers hidden." with **Remake quiz answers**). **Fallback:** starting a quiz still calls `ensureDistractors` for any card without them (never for a saved set that leaks: the builder just leaves it out), so the quiz starts either way (with a notice and true / false questions if that fails too). `ensureDistractors` is shared per lesson: the stage, a retry and quiz starts that overlap wait for one AI call (an `includeFailing` call that finds a missing-only run waits for it, then runs its own).
- **AI exam review** (`server/src/services/quiz-review.js`, the pipeline's `quiz_review` stage after `quiz_options`; Default model only): every card the quiz can ask is shown to a strict reviewer with all the forms it can be asked in (question, right answer, the right answer as a Yes/No statement, every wrong option and false statement that passed the code checks, each marked `mc` / `yes_no` / `both`; the prompt says another item or term of the lesson that does not answer the question is a good wrong option, `off_topic` means the lesson doesn't cover it at all, and an option that only rewords the right answer is `two_correct`; `two_correct` is judged by meaning, not words, with three examples on made-up topics (two kinds that both fit a definition, a reworded benefit, a reworded drawback) so the lessons we grade stay unseen; in code an `off_topic` flag is ignored when the option's text is found in `raw_text` (`comparable`, case/spacing/punctuation ignored), and the prompt says so too) and the lesson (all of it under 16K characters, else the blocks around the batch's quotes), 12 cards per call (`quizReviewPrompt`). Flags (`server/src/quiz/review-flags.js`): card `card_reveals` | `not_in_lesson` | `vague` | `off_topic` (made from the lesson's learning objectives / outline / agenda: written again, else left out; the quick-check review has the same flag); set `giveaway` (also when the right answer rules the others out by itself: "relevant" beside "all details" / "everything"; one echoed word of the question is allowed, rule b); true statement `giveaway` | `not_in_lesson`; option `two_correct` | `reversed` | `off_topic` | `giveaway` (a caricature or extreme: "all details", "everything", "always", "as long as possible"); card `not_in_lesson` also covers an invented cause or effect between listed items and a rewording with a new meaning; unknown flags are dropped; an item the reviewer leaves out of a reply that parsed counts as clean (saved with no flags, like a section in the quick-check review), the prompt asks for one entry for every item, and a reply that matches none of the batch's cards fails the batch (nothing saved, the cards stay pending) so an empty reply cannot mark everything clean. A wrong option or false statement that is the opposite of the right answer with no negative word ("Creates anxiety" for "Builds confidence") is flagged `reversed`; the wrong-answer prompt forbids it. The first call also groups the key terms into families. **One fix round**: a concept card's flagged options (or its whole set, for a set giveaway) are made again in one call per batch (`remakeFlagged`, label `the quiz answer options (after review)`, the reviewer's reasons given as the rejected answers; still not clean: settled); flagged cards (and an answer `not_in_lesson`) are written again in one call per batch (`regenerateCardsPrompt`, label `the flashcards the quiz review flagged`, each checked by `checkNewCard` like admin's Regenerate and saved in place, its wrong answers deleted and made again; **never once a participant other than P00 has records**: the card is then only left out). A rewrite that keeps every content word of the old card ("It is presented…" -> "This is presented…", `unchangedRewrite`) counts as failed: not saved, the card stays left out, and it spends no round-2 call. Round 2 (label `the quiz review (after fixes)`) reviews **every** card whose review went out of date in the fix round, not only the ones made again: a term card's new definition is another term's false statement, a concept card's new answer can be another card's option, so nothing is left "not reviewed yet"; whatever is still flagged is left out: a flagged card is not asked, a flagged option or false statement not shown, a flagged set not asked as multiple choice, a flagged true statement not as Yes/No. A term card's flagged options (other key terms) and a giveaway true statement are left out without a remake. Saved per card in `quiz_reviews` (migration 013) with a hash of the card's text and of everything shown, so it is cached: a card is reviewed again only when what the quiz shows changes (a regenerated card's old verdict no longer applies). A failed review leaves the lesson ready (the job is `failed` for admin); an unreviewed card is asked as the code checks allow. Admin's row (`quiz_review: { reviewed, flagged, pending, checks, status, error }`) says "AI review: N of M cards flagged." with **Review again** (`POST /api/admin/lessons/:id/quiz-review`: with cards not reviewed yet or changed since, the row says "N quiz questions aren't checked by the AI reviewer yet." and the button **Review quiz** reviews only those; with none, it clears every card's hash so all are reviewed again, with one more fix round), and `npm run quiz:check` prints the review with the flagged cards and why.
- Untimed. Time per question (`time_ms`, capped at 1 h) and total time (`duration_ms`) are recorded. Quiz results never touch flashcard scheduling or `flashcard_reviews`.
- Screen (`#/quiz/:lessonId`): "Getting your quiz ready" (after 2.5 s: "The AI is thinking up answer options…"), then the test sheet is handed out (slides up 32 px and fades in, 420 ms; a tap, Enter, Space or Esc skips; a fade under reduced motion), then one question at a time with no wait between them (no exit animation: the next question is the only one on the sheet), the progress as answer-sheet bubbles (`AnswerSheet`, `bubbleStates` in `lib/quiz.js`: answered filled, current a ring, neutral only; `role="progressbar"`). After an answer is saved it is marked in pen (`Pen.jsx`): a loop drawn round the chosen option's number, a tick on the right option, a strike through a wrong chosen one (one-line options only); a tap finishes them and Next never waits. The results' score is circled like a grade. After each answer: correct / not quite, the right answer and the card's "From the lesson: …" evidence; Next sits in the pinned action bar. Keys: 1-4 answer (1-2 on true / false), Enter next. A true / false question is **shown as Yes / No** (`yesNoAsk` / `yesNo` in `client/src/lib/quiz.js`; kicker "Yes or no?"): the thing judged is the big heading, a smaller line says what it is judged against, and a short question sits above the buttons Yes / No (`yesNoAsk` returns `{ heading, label, context, ask }`; the heading is the focus target, the options group is labelled by heading and question, and `questionText` reads them in that order): a term card shows the **term** as the heading, "Suggested meaning:" + the definition, then "Does this match?"; a concept card shows the **suggested answer** as the heading, "For:" + the card's question, then "Is this the answer?". The first letter of an option, of the suggested answer and of the shown definition gets a capital for display only (`capitalFirst`; "iPhone" / "pH" are left alone; the stored text is never changed). The results list ("Missed questions": the question, "Your answer", "Right answer" as Yes, or No plus the real answer) uses the same wording. It is display only: `choices`, `chosen_answer`, `right_answer` and the export stay True / False, and the codebook says so. Focus moves to each new question, then to Next (described by the feedback), then to the results heading.
- Results: score, percent, time, comparison with the best earlier score, the missed questions (your answer, right answer, evidence), **Retake** (same questions, new question order and option order, shuffle again) and **Back to lesson**. The Flashcards done card's main action is "Take the mock quiz".
- Tables (migration 007):
  - `quiz_reviews` (flashcard_id PK → flashcards ON DELETE CASCADE, lesson_id, card_hash, item_hash, card_flags / set_flags / true_flags JSON `[{ flag, why }]`, option_flags JSON `{ option text: [{ flag, why }] }`, round 1 | 2, made_by, reviewed_at; migration 013, which also adds `lessons.term_families`): the AI exam review, shared like the cards, never exported. `quizBuildOptions` (`server/src/quiz/options.js`) reads it (and the families) for the quiz routes, admin's leak report and quiz:check, and works without them on an older database.
  - `quiz_distractors` (flashcard_id PK → flashcards ON DELETE CASCADE, choices JSON of 0-3 wrong answers, made_at, `settled` 0/1 (migration 010; `npm run quiz:check` never reads it, so it works on older databases))
  - `quiz_attempts` gains `started_at`, `finished_at` (NULL for a quiz left part-way), `duration_ms`, `retake_of` (the attempt whose questions it reused; NULL for a fresh quiz). `score` is final once finished.
  - `quiz_answers` (id, attempt_id → quiz_attempts ON DELETE CASCADE, position, flashcard_id ON DELETE SET NULL, type `mc`|`tf`, kind `term`|`concept`, question, statement (tf), choices JSON, answer_index, answer_text, evidence, chosen_index, correct, time_ms, answered_at): one row per question, written at start and filled in when answered; a full copy, so it outlives card changes. Phase 6 reads it.
  - `quiz_questions` (001) is unused: questions are built from flashcards per attempt.
- **Resume:** `POST /api/lessons/:id/quiz/attempts` without `retake_of` returns the lesson's newest unfinished attempt if it started less than 2 hours ago (200, `resumed: true`, `next_position` = first unanswered question or `null` when all are answered, `elapsed_ms` = time already spent), so a reload or coming back never creates a second attempt. Older unfinished attempts are left as they are (abandoned). A retake always starts a new attempt. The results screen offers "Review these flashcards", a plain link to the lesson's flashcard deck; it changes no scheduling.
- Endpoints: `GET /api/quiz` · `POST /api/lessons/:id/quiz/attempts` (body `{ retake_of? }`; returns questions without answers) · `POST /api/quiz/attempts/:id/answers` (`{ position, choice, time_ms }`; each question once; returns correct, answer_index, answer_text, evidence) · `POST /api/quiz/attempts/:id/finish` (`{ total_ms }`; every question answered first; returns score, missed questions, previous best).
