1. pdf-strays.js:26-35,86-90 + pdf.js:122-124: applyStrays can change text in a clean PDF. Any letters-only item of 1-3 letters ("A", "of", "ATP": a diagram label or overlapping text box) that sits inside a longer item with the same size and baseline gets written into the nearest space. Probed: 87 of 219 x positions over one line merged words ("TheAcell membrane", "mgaohay"). The repaired text becomes raw_text, so cards and the Original text view inherit it. Fix: decide per document. Run findStrays on every page first, then call applyStrays only when damageReason gives 'stray_letters', or when a page has at least 2 placements. Also require one token next to the gap to be "broken" per text-damage (no vowel / bad onset).
2. pdf-strays.js:58: findStrays is O(strays x items) per page and synchronous. Probed: 5000 items 133-185 ms, 10000 items 571 ms. A 200-page PDF with 5000 items per page adds about 37 s to the 60 s PDF_BUDGET_MS (pdf.js:10), so a file that passed before can now get a 422, and each page blocks the event loop for every user. Fix: bucket candidate hosts by Math.round(transform[5]) (and size) in a Map once per page, check only those buckets, and skip items with str.length <= 2 as hosts up front.
3. text-damage.js:17-19: single-letter variables count as broken ("let x be", "where n is"). Probed: algebra prose 31% and stats prose 25% → broken_words. Filipino text-speak ("lng", "tlga", "kc", "nyo to") gives 20% → flagged, a real risk for students' own notes. Real math-calc-exp-log-mit.pdf is already at 4.3% of the 7% limit. Fix: count lone consonants apart and require at least ~8 broken multi-letter tokens. Optionally add lng/nmn/tlga/kc/lcm/gcd/csc to NO_VOWEL_OK.
4. text-damage.test.js:25-26,57-61: the MATH case is one math sentence in about 130 words of English, so it barely tests anything. Add a full math paragraph and a Taglish text-speak case with the expected outcome (it fails today, see W3).
