# StudyRevr

Open-source, mobile-first study app. Students upload a lesson (.docx / .pptx / .pdf); an AI generates a sectioned review, flashcards (Anki-style spaced repetition), and mock quizzes. Built for a Practical Research 2 study comparing traditional studying vs AI-assisted studying, so study activity must be logged and exportable.

## Stack
- Backend: Node.js (LTS) + Express, ES modules
- DB: SQLite via better-sqlite3 (single file, migrations on startup)
- Parsing: mammoth (docx), officeparser + jszip (pptx), unpdf (pdf). Reject .doc/.ppt with a clear "save as docx/pptx" message. Scanned/image-only PDFs are accepted but flagged with a warning (no OCR).
- `raw_text` format: blocks separated by a blank line, one paragraph per line inside a block. A block is a pptx slide or a PDF page (a paragraph that runs over a page seam stays whole, in the page it starts on); for docx every paragraph is its own block. Word count and the low-text warning are computed on this final text.
  - pptx slide block: slide text (bullets as `- item`, numbered as `1. item`, table rows as `a | b`; every line of a paragraph is its own line, `textLines` in `server/src/services/pptx.js`: a line break (`<a:br/>`, `_x000B_`, U+2028) and two runs that officeparser glues with no space ("trust.Share": a lowercase sentence end straight before a capital) are split, so each bullet line is its own `- ` bullet and a numbered item keeps its number on its first line only; abbreviations like "e.g.Example" are not split), then SmartArt text read from `ppt/diagrams`, then, when the `include_speaker_notes` setting is true (default; `settings` table, no UI until Phase 7), a line `Notes:` followed by the speaker notes. Slides are emitted in deck order.
  - pdf: lines repeating on most pages (headers/footers/page numbers) are stripped; wrapped lines are reflowed into paragraphs, `word-`/`next` line-end hyphens are joined (hyphen kept), inline `»`/`•` bullets get their own line, and a page that starts lowercase after an unterminated sentence is merged into the previous paragraph.
- Uploads: multer, 20 MB limit, extension + MIME check + file signature check (zip `PK` for docx/pptx, `%PDF` for pdf)
- Validation: zod for all AI JSON output and request bodies
- Frontend: React + Vite, Motion (`motion` package, formerly Framer Motion) for animations. Stats is drawn in CSS (no chart library).
- Single repo: `/server` and `/client`, root scripts to run both in dev
- Install: `npm ci` in the repo root only. `server/` and `client/` are npm workspaces with one root `package-lock.json` and `node_modules/`; `npm ci` inside `client/` (or `server/`) wipes the root `node_modules` and installs only that workspace. The lockfile's `libc` fields come from npm 11: installing with npm 10 drops them without any real change, so don't commit that churn. `overrides` pins `shell-quote` ^1.12.0 (concurrently pins a vulnerable 1.9.0). `allowScripts` in the root `package.json` approves `better-sqlite3`'s install script (it fetches or builds the native binary; unpinned, so an upgrade stays approved) and denies `tesseract.js`'s postinstall (only an opencollective banner, pulled in by officeparser), so `npm ci` needs no manual step and prints no install-scripts warning. npm 11.19 still runs unreviewed scripts and only warns, but under `--strict-allow-scripts` (or a later npm that enforces it) an unapproved package fails `npm ci` with `ESTRICTALLOWSCRIPTS`; a new dependency with an install script needs `npm install-scripts approve <pkg>` (or `deny`), then check that `npm install-scripts ls` reports none unreviewed. Checked on a fresh clone: `npm ci --strict-allow-scripts`, then `new (require('better-sqlite3'))(':memory:')` from `server/` works (better-sqlite3 loads its binary only when a database is opened, so a bare `require` can pass without it).

## Conventions
- Plain JavaScript (no TypeScript) unless asked otherwise
- Keep files small and focused; one route file per feature
- No secrets in code; config via `.env` with a committed `.env.example`
- Mobile-first CSS, dark mode via `prefers-color-scheme` + manual toggle
- Look: a study journal (`client/src/styles/tokens.css`; mockups and the decision in `design/`). A plain page with a margin column (`--mw`, `--mgap` of 20px or more to the text) where the numbers that matter are written (`.mnote`, or a row that hangs into it, `.hang`). The margin's edge is a 1px neutral hairline (`--line`), drawn by `.main::before` only on pages whose margin holds numbers (see the `:has()` list in `shell.css`); an empty margin and the reader get no line, and nothing red means wrong. In the AMA themes the text is the same `--ink` / `--ink-2` as Light (AMA) or Dark (AMA Dark), and the red is the brand and means "go": page titles, the margin line, the header rule and the primary buttons (`--margin` for titles, line and rule; `--ink-btn` for buttons: AMA maroon #7A1B1B with white text; AMA Dark, which is Dark's own neutral paper, sheet, text and lines with no blue tint, AMA's own maroon #7A1B1B with white text 10.5:1 and a 1px lighter edge of the same hue `--ink-btn-edge` #CE2E2E (3.4:1 against the paper, since the fill alone is 1.6:1), and the same red lightened only to the darkest shade that reads, #DE6868 (5.2:1 on the paper, 4.7:1 on the sheet), for titles and lines, which need 4.5:1 / 3:1; its focus ring and pen loop are gold, the Easy rating keeps Dark's blue, and blue is otherwise only for links). In Light and Dark `--margin` is only the logo's rule. Rules only under list rows; decks, flashcards and the end card are index cards (`--card-shadow`, `--r-lg` 2px; a deck shows two card edges under it, drawn in `--card-edge`); primary buttons are solid ink (`--ink-btn` / `--on-ink-btn`: navy in light, pale ink in dark), quiet buttons a ruled outline (`--ink-btn-press` is the primary button's pressed/hover colour). The edge of every control (quiet button, chip, option, rating button, upload zone) is `--control-border`, at least 3:1 against paper and sheet in both themes (light 3.9 on paper, 4.3 on sheet; dark 4.4 and 3.9; `--line-strong` stays for decorative rules). The pinned Previous/Next, Next question and flashcard answer bars have no frame: a paper background and one top hairline. On a wide screen the page and the desk behind it sit inside `--book-max` (84rem). Header, page and tab bar add `--safe-top/right/bottom/left` (device insets). There is one small radius, `--r-sm`. The highlighter is `.mk`: in light a marker stroke under the words (`--mk-top` 54%, the ink stays ink), in dark a bright marker over the word with dark text (`--mk-top` 10%, `--mk-ink`). Navigation is plain: the open tab is only its label highlighted (a bottom bar on a phone that respects `--safe-bottom`; from 56rem a quiet icon + label column beside the page). Learning counts use `--learn` (pencil amber), never red. The reader (`.lesson-view`) uses a slim 14px margin at every width so text and the quick check get the page (the section number is on the "3/8 sections" line); from 56rem the page is a sheet on the desk (`--desk`), and wide screens use two columns (decks beside All lessons, the quiz check and original text beside the reading, results beside the score, flashcards and quiz scores beside the week).
- Respect `prefers-reduced-motion` (skip non-essential animations), and the **Motion setting** (Settings › Appearance: Match my device (default) / Less motion / Full motion; `client/src/lib/motion.js`, kept like the theme: localStorage `studyrevr-motion` on this device, not per participant, written to `data-motion` on `<html>`). `useMotionReduced()` is the one source of truth for every animation (never `matchMedia` or motion's own `useReducedMotion`, which only know the device); `MotionConfig` gets `always` / `never` from it. CSS follows the same rule: `@media (prefers-reduced-motion) { :root:not([data-motion='full']) … }` plus `:root[data-motion='less'] …` (base.css, review.css). Less motion is exactly the reduced behaviour, Full the full one, Match follows the device live. It is visual only: the answer clock never reads it, so `time_ms` is the same with every choice (`client/test/clockScreens.test.js` runs every choice on a reducing and a full-motion device).
- Paper motion (`design/motion/`: the proposals and a static demo): things move like paper and pen, with transform / opacity only (plus `stroke-dashoffset` for pen strokes), each under ~600 ms (the deck coming out is the one exception), every one skippable by a tap and never blocking input; reduced motion: off or a plain fade. No new colours or radii: pen marks use `--accent` (the loop), `--ok` (the tick), `--ink-2` (the strike). Nothing red means wrong in Light and Dark; in the AMA themes red is the brand (titles, primary buttons, text links, the margin line and the header rule) and the quiz's teacher's-red-pen marks (`--margin`: the strike through a wrong option and the X beside it, ≥3:1), and nowhere else: never an error, "Again" or a status. Text links are `--link` (AMA #7A1B1B; AMA Dark #DD6363, a step lighter than the titles because the end card's links sit on the sheet), always underlined, hover a step darker / lighter, visited in between, ≥4.5:1; the focus ring and the quiz's student-pen circle stay blue in AMA, and in AMA Dark the focus ring is gold and the circle the link red (`--accent` lavender stays only for the Easy rating). A wrong answer always keeps its icon and its strike shape, so it never relies on colour: the wrong option's text and "Not quite" stay `--ink-2`, the circle round the picked number stays blue (`--accent`, the student's pen), the tick `--ok`, the right answer on the gold marker. Everywhere else wrong answers, the "Again" rating and errors use `--ink-2` / `--learn` with an icon and a word. Destructive buttons (admin delete, "Yes, remove it") never look like a primary button: in the AMA themes they are an outline with the trash icon and the word (`.btn--destroy`; admin's in `--danger`, a student's in ink), so red never means both "go" and "danger"; `--danger` is only for admin-only destructive buttons. Blue stays for focus rings and the active nav icon (AMA); gold is only a fill behind dark text.
- **Answer time excludes animation and time away** (`client/src/lib/answerClock.js`, pure and fake-clock tested in `client/test/answerClock.test.js`; `hooks/useAnswerClock.js`): a flashcard's or quiz question's `time_ms` starts when it is on screen and usable (its entrance ended or was skipped, or at the first paint when there is none) or at the first tap or key if that comes sooner; the flip pauses it (reason `flip`) and so does the app being hidden (`visibilitychange`, reason `hidden`: the clock runs only while no reason is held, so a card finishing its turn in the background does not start it); a flashcard cannot be rated (buttons or keys 1-4) until `onTurned` (`canRate`; a 1.5 s fallback opens it if the end of the turn is never reported); the marks drawn after an answer play after it is recorded and never delay the next clock; a failed save reopens it. The same events give the same `time_ms` with reduced motion on or off. A reload restarts the open card's or question's clock at 0 (the codebook says so). The export codebook says rows answered before the study copy was updated to this version counted the animations of that time and did not pause when hidden (the researcher notes the day they update).
- Every AI call: strict "use only the provided lesson text" instruction, zod validation, one retry on invalid JSON, clear error surfaced to UI
- Provider errors become actionable messages (`server/src/ai/client.js`): 400 check the model in Settings (unless the body says the key is invalid, as Google's does: then the key), 401/403 check the API key in Settings, 404 model or base URL, 429 rate limited, try again shortly, timeout the provider is slow, retry. The provider's own error body is logged server-side with keys redacted and never shown in the UI.
- Every AI prompt that receives lesson text must explain that a `Notes:` line inside a slide block marks the teacher's spoken explanation of that slide: treat it as lesson content that elaborates the slide, not as a separate topic
- Long-running generation is async: create a job, frontend polls status

## AI Layer (provider-agnostic)
One adapter speaking the OpenAI-compatible `/v1/chat/completions` API. This covers Google Gemini, NVIDIA NIM, Ollama (`/v1`), llama.cpp server, OpenRouter, and similar.
- **Default provider: Google AI Studio** (Gemini, OpenAI-compatible endpoint). Key in `.env` as `GOOGLE_API_KEY`. The project's key has, for `gemini-3.5-flash-lite`, **500 requests/day, 15 requests/min, 250K tokens/min** (free tier).
- **AI calls per lesson** (Default model, Google, a lesson that fits one chunk): sections 1 (+1 second try for the quick checks whose quote fails in code), key points 1, key terms 1 (+1 merge when chunked), flashcards 1 per chunk (+1 for list items still without a card), quiz options 1 per 15 concept cards (+1 second try per batch), quiz review 1 per 12 askable cards, and only when something is flagged, per review batch: 1 remake of flagged options, 1 rewrite of flagged cards (+1 quiz options for rewritten concept cards) and 1 round-2 review (of every card whose review went out of date); quick-check review 1 per 12 sections with quick checks (+1 rewrite and 1 round-2 review when one is flagged). A small lesson (12 cards or fewer) with nothing flagged is about 8 calls, with flags 9-14; a 30-card lesson about 10 with nothing flagged, up to about 23 if every batch is flagged. So 500 a day covers roughly 40 small lessons (fewer when live taps and Prepare, 2 calls per section, share the day). Processing runs at 12 requests/min (3 of the 15 kept for live calls); a review call sends at most 32K characters of lesson (the whole lesson when under 16K) plus its items, so even 12 calls a minute stay under 250K tokens/min.
- **Presets** (`server/src/ai/providers.js`): `google` (default), `deepseek` (`api.deepseek.com/v1`, `DEEPSEEK_API_KEY`), `qwen` (DashScope international, `DASHSCOPE_API_KEY`), `nvidia-nim`, `openrouter`, `ollama`, `llamacpp`, plus `custom`. A preset is a base URL, default model, chunk tokens, concurrency, temperature (0.2), the `.env` key name and whether `response_format` json_schema is supported. Google: ~30000-token chunks, concurrency 2, json_schema on. The other presets keep small-model chunking (2400 tokens). Default model: `gemini-3.5-flash-lite` (id confirmed from Google's `/models`; a `models/` prefix is always stripped).
- **Model resolution order, per provider:** one-off request value (e.g. test-ai body) > Settings (`settings` table) > `.env` (`AI_MODEL`) > preset default. The model is never fixed: `GET /api/settings/models` lists the provider's chat models (embedding, image, video, TTS, live/audio, ASR, rerank, `aqa`, `deep-research-*`, `antigravity-*`, `*computer-use*`, `nano-banana*`, `*-customtools`, `gemini-omni-*`, Qwen's wan/wanx/cosyvoice/paraformer/sambert etc. are filtered out, `server/src/ai/models.js`) and a free-text model id is always accepted if `/models` fails or is empty. The active provider and each provider's last model are saved separately (`ai_provider`, `ai_model:<provider>`), so switching providers restores that provider's model.
- **Keys are per provider:** `GOOGLE_API_KEY`, `NVIDIA_API_KEY`, `OPENROUTER_API_KEY` in `.env`, or saved in Settings (`ai_api_key:<provider>`). Only the active provider's key is ever sent. The API returns only a "key set: yes/no" flag; keys are never logged or returned, and a backup export must exclude `ai_api_key:*`. The SQLite file holds saved keys, so it is git-ignored. Every way a key is deleted (Remove my key, Delete all student keys, replacing a key, `participant:delete`) turns on `secure_delete` and then runs `wal_checkpoint(TRUNCATE)` (`wipeDeletedKeys` in `services/student-ai.js`): in WAL mode the old page stays readable in the `-wal` file until a checkpoint, so `test/student-key-wipe.test.js` scans the db and `-wal` files for the key afterwards.
- Optional `.env` overrides `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`, `AI_EXTRA_BODY` (JSON merged into the request body, zod-validated, ignored if invalid) apply only to the `.env` provider (`AI_PROVIDER`). Tuning: `AI_CONCURRENCY`, `AI_CHUNK_TOKENS`, `AI_TEMPERATURE`, `KEY_TERMS_MAX`.
- Calls within one pipeline stage run in parallel up to the concurrency limit; stages stay in order (sections, key points, key terms, flashcards, quiz options, quiz review). 429/5xx/network errors retry with growing, jittered waits (Retry-After honored: header in seconds or a date, or Google's `retryDelay` in the body; at most 60 s). Request timeout is a preset value (`AI_TIMEOUT_SECONDS` overrides): Google 60 s, every other preset 300 s; a timed-out request is retried once. The reply body is read inside the timed attempt, so a stalled body is a timeout too.
- **Per-model tuning** (preset `models`): `{ timeoutMs, requestsPerMinute, extraBody }` replace the preset's for that model id (`extraBody` is merged into that model's requests, under `AI_EXTRA_BODY`). Google `gemini-3.5-flash-lite`: 25 s timeout, 15 requests/min. `gemma-4-26b-a4b-it` (the live fallback): 25 s, 30 requests/min, `reasoning_effort: "minimal"` (Gemma refuses "none"/"low"; without it it thinks for 25-30 s and can spend all of max_tokens; measured with it: Explain simpler 4.7-5.9 s, Taglish 9.4-12 s). `gemma-4-31b-it`: 60 s (measured 33-50 s), same options. `requestsPerMinute` is a client-side limit per host + model + key (`server/src/ai/ratelimit.js`) that every HTTP attempt takes a slot from, retries included; under it, a 429's Retry-After holds every call to that model.
- **Thinking for lesson processing** (setting `lesson_thinking`, Minimal / Low / Medium / High, **default Low**; admin: "Think harder when preparing lessons"; migrations 015 and 016 (016 moves an `off` setting to `low`; a legacy `off` value still reads as Minimal); `generateJSON({ reasoning: 'low' | 'medium' | 'high' })` (`THINKING_EFFORTS` in `ai/client.js`), `reasoningEffort: true` on the google preset only): above Minimal the call sends `reasoning_effort` of that name (after `AI_EXTRA_BODY`), raises `max_tokens` by 8000 (at most 32000, since thinking counts against it) and the timeout to 120 s; Minimal sends nothing (the model's default does no thinking; `"none"` is a 400 on Gemini). The runner (`pipeline/run.js`) wraps `generateJSON` so every processing call asks for the level (sections, key points, key terms, flashcards, list-item coverage, quiz options, quiz review and its fix rounds, quick checks and their review), and above Minimal the four content stages (sections with their quick-check second try, key points, key terms with the merge, flashcards with the list-item call) also get `RESTATE_ONLY` appended to the system message: "Think as much as you need, but your output may only restate what the lesson says. Never add explanations, examples, causes or connecting sentences of your own." Nothing else thinks: live Explain simpler / Taglish, Prepare, the student quiz-start fallback, admin's single-card Regenerate and Test connection. Other providers run as Minimal. `lessons.thinking_level` (`minimal` | `low` | `medium` | `high` | `mixed`, NULL = made before the setting; migration 016, a plain column backfilled from `processed_thinking`, which is no longer written) is written when a run starts its first main stage (a failed or retried run is recorded too; a retry at another level, or a quiz-answers / review run on an older lesson at a level other than Minimal, makes it `mixed`); admin's list and preview say "Prepared with thinking: …", `lessons.csv` exports it, and `ai_calls.thinking` is `off` on every live row (`ai_thinking`). Changes of the setting go to `admin_events` (`setting_changed`, `lesson_thinking=low`). `stats` counts `thinkingCalls` / `thinkingTokens` and the `[ai]` log marks `(think=low)`. **Measured** (branch `feat/thinking-test`, 2026-10-17): a probe of `gemini-3.5-flash-lite` accepted all four values (reasoning tokens on a small puzzle: none / minimal 0, low 0, medium 359, high 619). Three lessons (RSCH2120 Data Collection Methods pptx, Nature of Inquiry and Research pptx, Week 1 Introduction to AI pdf), one run each at Minimal, Low and Medium, graded blind on wrong / not in lesson / two correct / bad quote / giveaway / missing / vague, score 3·High + 2·Medium + 1·Low (no High issue in any run): RSCH Minimal 21, Low 25, Medium 27; Nature 32, 13, 20; AI 22, 13, 28. Time / AI calls: RSCH 18 s / 9, 63 s / 13, 91 s / 15; Nature 63 s / 13, 63 s / 13, 90 s / 17; AI 69 s / 14, 66 s / 14, 105 s / 19; no retries or timeouts. Low won 2 of 3 under the rule fixed beforehand, so it is the default; Medium still padded sections despite the restate line. Caveats: one run per cell; Low changes two things (thinking and the restate line; Minimal plus the line is untested) and may think very little (0 tokens in the probe); much of the spread is wrong options that are synonyms of the right answer. The earlier High measurement (self-introduction lesson: 120 s, 13 calls, invented sentences in four sections and four key points, the key-element cards dropped) still stands. `npm run pipeline -- --thinking=minimal|low|medium|high` runs a lesson at any level. **Check after the quiz-check fixes** (branch `fix/quiz-checks`, 2026-10-17): RSCH2120 made again at Low with the five fixes, graded on the same 7 categories against the earlier Minimal version (the grader knew which was which, and the old one predates rule l, so this is not blind): old 27 (9 Medium: four "one / second / third / fourth way" cards, "Where can one of the types…", four missing list groups; 9 Low), new 16 (1 Medium: no card for the four ways data helps researchers; 14 Low). The new reviewer flagged every synonym wrong option (about 30 across 13 cards) so none reached a student, but it also flagged sibling options on the "Cross-Sectional Surveys" term card as `two_correct` (over-flag, the card is then not asked as multiple choice). One run per version.
- **Attempt log:** the client reports every HTTP attempt to `onAttempt` (`throttle` / `start` / `ok` / `fail`, failure reason `timeout` | `rate_limit` | `server` | `network` | `http_<status>`). The server logs each as `[ai] ...`, `npm run pipeline` (`-- --thinking=minimal|low|medium|high`) prints them with times, and `stats` counts attempts, failures and retries by reason (timeouts included). `npm run pipeline` also wraps the process's `fetch` (`server/src/ai/netlog.js`) to log and count every HTTP request from any code and flags a mismatch with the client's count, reports event-loop stalls, and the flashcards stage logs its time split (AI calls / checks and de-duplication / saving).
- **Grounded key terms:** each key term comes with an `evidence` quote (at most 25 words) copied from the lesson. In code the quote must exist in the lesson text (case, spacing, punctuation and line-end hyphens ignored) and must say more than the term or a title; otherwise the term is dropped and logged. Evidence is stored in `key_terms.evidence` for the Review UI. Key terms are domain concepts only (no list-item examples or evaluative phrases), de-duplicated across chunks (case- and plural-insensitive, in code), at most `KEY_TERMS_MAX` (12) per lesson.
- **Key-terms merge:** a lesson split into several chunks gets one extra call (`the merged key terms`) after the per-chunk calls. It receives every candidate term with its definition/evidence versions and returns only candidate numbers (and which version): it can drop evaluative phrases, examples, weak terms and synonyms and pick the best version, but cannot add terms or write evidence. The grounding check runs again afterwards against the whole lesson. An unusable reply keeps all candidates (capped) rather than erasing the terms. Single-chunk lessons skip the call.
- **Live calls** (Explain simpler, Filipino/Taglish; `server/src/ai/live.js`, `server/src/services/live-rewrite.js`): a fallback chain, one try per step (`live: true`: no HTTP retry waits, no timeout retry, and a request that would wait over 3 s for the client-side limit fails at once as a rate limit; a real 429 pauses the limiter for that model for its Retry-After, so later live calls skip straight to the next step): the student's own key (when admin allows it and they saved one) → the admin Default → `GEMMA_MODEL` (`gemma-4-26b-a4b-it`) on the admin's Google key (skipped without a Google key or when Default is that model) → error "The AI is busy, try again in a minute." (rate limit) / "The AI couldn’t answer right now. Try again in a minute." (every other failure: outage, retired model, rejected key, unusable reply) with Try again. **Students never see a provider message or a pointer to Settings** (`finalError` in `live-rewrite.js`); the real reason is in `ai_calls.error_code` / `fallback_reasons` and admin sees it (see Admin, `GET /api/admin/ai-problems`). Every step falls back on `rate_limit`, `timeout`, `network`, `provider_error` (5xx); Default and Gemma also on `invalid_json` / `bad_response` (the model gave nothing usable); the Default also on `not_found` and `bad_request` (a retired or mistyped Default model, which some providers answer with 400: Gemma is a different model and still answers, with the "backup AI" note); the student step also on `auth` (401/403), `no_credit` (402), `not_found` and `bad_request` (a retired or unsuitable model: Default is another model). A rejected key, no credit or a missing key/model on the Default does not fall back (Gemma uses the same admin key); the student sees the plain "couldn’t answer" message and admin sees the reason. `ai_calls.fallback_steps` is how many times the request moved on to the next step: the failed steps before the answer, or, when nothing answered, the steps tried after the first (a rejected key on the Default alone is 0; Default then Gemma both failing is 1). The student's timeout is 25 s like the other steps. The routes need a participant code (`requireParticipant`): no code, no AI call. Gemma is limited to 8 requests a minute (its 16K tokens a minute are the real limit), retries once at once on a provider 5xx only (not a timeout; logged as `gemma:provider_error` in `fallback_reasons`), and taps on the same section and kind while it answers share one Gemma call (`coalesce` in `live-rewrite.js`, like the Default's; its answer is still never cached). Gemma gets only the section and capped answers (`SMALL_MAX_TOKENS`: 1200 simplify, 2000 translate); the system message works with Gemma (no need to move it into the user message); its `<thought>…</thought>` blocks are stripped before JSON parsing (`server/src/ai/json.js`). Only Default answers become the shared cached version (`saveSharedVersion`, first one wins, with `*_made_by`); student-key and Gemma answers are returned to that student only and not stored. Only the request that stored the Default's version has `saved_shared = 1`; a tap that joined it, or one that finished after Prepare (or another tap) saved a version, shows the stored shared version (so everyone reads the same text) and logs `from_cache = 1`. A student with a saved key always gets a live call from their key; without one, a cached shared version is served with no AI call. A response carries `answered_by` and `fallback: { steps, note }`; the client shows the note under the rewrite ("Your key didn’t work, so the default AI answered." / "The main AI was busy, so a backup AI answered." / "Your key didn’t work and the main AI was busy, so a backup AI answered."). Every live request writes an `ai_calls` row and an `[ai-live]` log line. Lesson processing never uses the chain, a student key or Gemma.
- Interface: `generateJSON({ system, user, schema })` → validated object
- Separate calls per feature (sections/summary, key terms, flashcards, quiz). Never one giant call.
- **Sections follow the lesson** (`sectionsPrompt`, `sectionRange` in `server/src/pipeline/generate.js`): one section per heading or group of neighbouring slides, a list heading ("Purpose", "Key elements") its own section, never one section for the whole lesson; each call is told "between X and Y sections": X = the larger of the summary length's target and min(ceil(topics / 2), ceil(words / 80)), Y = min(topics, ceil(words / 60)) (at least X), where topics = the chunk's slides / pages (else its heading-like lines). Every item of a list the lesson stresses is named in its section.
- **Lesson words only**: key-term definitions, card answers and rewritten cards use the lesson's own words (no added describing words such as "created" that the lesson doesn't use); sections, key points, flashcards, both card rewrites and the quick-check rewrite also get `KEEP_MEANING` (`server/src/ai/prompts.js`): never connect listed items with a cause, effect or purpose the lesson doesn't state ("because", "so that", "to …" only when the lesson says it; listed items stay separate, never "share your background to encourage meaningful communication"), and never reword into a new idea ("workplace readiness" for "professionalism", "fostering confidence" for "trust"), though plain synonyms that keep the meaning are fine (a blanket "keep the lesson's own key words" made every question about a bare list item name its answer, so rule g dropped 8 of its 10 cards); a flashcard about a list item the lesson says nothing more about describes it in plain words with the same meaning, never by its own words or its place in the list ("the first purpose"); key points take only "a cause and effect the text states" and never merge two listed items with an invented link; flashcards ask "why" only when the lesson gives the reason; flashcard questions name their topic in full ("Which key element of a self-introduction…", never "your presentation" or "it"); wrong answers are believable to someone who hasn't read the lesson (no caricatures or extremes, nothing the lesson says is right, no other item of the same list).
- Chunk long lessons by paragraph (one line of `raw_text` = one paragraph), packing paragraphs up to the token budget so small local models (~8k context) work. Slide/page blocks and headings are soft boundaries: prefer to cut between blocks, never split a paragraph, and keep a slide's `Notes:` with its slide where it fits.
- Request JSON only; strip code fences before parsing

A student can **Try again** on their own failed upload (`POST /api/lessons/:id/retry`), which does not use an upload (but waits like an upload when the queue is full: 429 `upload_busy`). Known and accepted: a student can still retry their own failed upload while uploads are switched off (the lesson already exists and the retry is free), and processing can starve if live taps stay above about 12 a minute (processing gets 12 of the 15 requests a minute, live calls go first). A server restart fails the lessons it interrupted and logs `lesson_upload_failed` `processing:interrupted` for each student upload. Older provider messages never reach a student either: the quiz's fallback notice, a failed flashcards job (`/flashcards/decks`) and a failed Prepare (`section_versions.error`) are plain lines (`CARDS_FAILED_MESSAGE`, `PREPARE_FAILED_MESSAGE` in `lesson-access.js`). **A student never receives the file name** (list, lesson, upload response; admin does); the title comes from the file name (cut to 200 characters) and the student sees it on their own lesson.
- **Delete**: a student can delete their own upload only while it is private and **before it has any study record of theirs** (a flashcard answer, or a quiz attempt with at least one answered question, or a reading session with active time above 0; opening Review (a 0 ms session), opening the quiz without answering, and quiz or flashcard time without an answer do not count; `ownerRecords`). Deleting also removes the owner's `events` and `study_sessions` for that lesson in the same transaction (unanswered attempts go with the lesson): left behind they would lose their lesson (`lesson_id` NULL) and be counted in the teacher-only measures of `summary.csv`. The trade-off: a simpler / Taglish tap on a private upload that is then deleted disappears from the `_all` twins too; the `lesson_deleted_by_student` row in `lesson_events` stays. Once it is shared or studied, the delete option is gone (409 `lesson_shared` / `lesson_studied`). Admin's delete keeps its old rule (blocked once any participant other than P00 has records).
- **Share** (`POST /api/lessons/:id/share`, admin): a ready, private student lesson becomes visible to everyone. One way, no undo; the admin row asks first. Logged in `lesson_events` (`lesson_shared`, actor `admin`, participant = the owner) and `admin_events` (`lesson_shared`).
- **Events** go in a new table, **`lesson_events`** (migration 012), not in `events`: `events.type` has a CHECK constraint, so a new type would mean rebuilding that table (same reason as `setting_events`, migration 011). Types: `lesson_uploaded` (detail = file name in the database, the extension only in the export), `lesson_upload_failed` (detail = `too_large` | `wrong_type` | `bad_signature` | `wrong_content` | `unreadable` | `no_text`, or `processing:<stage>`), `lesson_deleted_by_student`, `lesson_shared`. `lesson_id` is a plain integer and the title is copied, so a deleted lesson's events survive. A refused upload (switch off, quota, busy) is not an upload and is not logged.
- **Research export**: `lessons.csv` (origin admin / student, shared, owner code; P00's private uploads left out unless `include_p00`, a shared one stays) and `lesson_events.csv`. **In the exports only, a student's upload is titled `Student upload <lesson_id>`** (`lesson_title` in every file, `title` in lessons.csv, the `L<id>` list in the codebook: `server/src/export/titles.js`) and `lesson_events.detail` of `lesson_uploaded` is only the extension, because the title comes from a file name that can hold a name; the database, admin's screens and the student's own library keep the real title, and the teacher's lessons keep their titles everywhere. In `summary.csv` the main lesson-dependent measures count `origin = 'admin'` lessons only (plus the All lessons deck, which has no single lesson), and each has an `_all` twin right after it that counts every lesson (the teacher's, shared and private uploads); `retention_quiz_first_pct_L<id>` covers the teacher's lessons and shared uploads. `self_monitoring_stats_views` has no twin. The codebook says all of this.
- **Withdrawal** (`participant:delete`): the participant's private uploads are deleted with their cards and quizzes; shared uploads stay, lose the owner (`owner_participant_id` NULL, `origin` stays `student`, so the export still reads "student upload, owner withdrawn") and the preview says so. **Backup / restore** carry uploads automatically (they are rows in the database).
- Client (`LibraryScreen.jsx`, `LessonRow.jsx`, `lib/uploads.js`): a compact upload zone with "N uploads left today" only while the switch is on (`GET /api/my-uploads`); own lessons say "Only you see this" / "Yours, shared with everyone", show the preparation stage, and a failed one shows its message with Try again; Delete appears only when the server says `can_delete` and asks in place with an ink button (never red). Admin's row says "Uploaded by P07 · only P07 can see it" and has **Share with everyone**.

### Upload
Drag-drop or pick file → progress states (admin's processing page): review sections → key points → key terms → flashcards → quiz answers → done. Accepts .docx, .pptx and .pdf. Warn if extracted text is very short (e.g. image-heavy slides); for PDFs with almost no text, warn that it looks scanned or image-only.

### Review
- Lesson list → lesson view
- Key points at top, estimated reading time
- Summary split into bite-sized sections with progress bar ("3/8 sections")
- After each section: 0–2 quick-check questions (none when nothing held up); the answer lies in its place under an index card that **Show answer** slides off (`QuickCheck.jsx`, 280 ms; a fade under reduced motion), then focus moves to the answer
- Per section buttons: "Explain simpler" (ELI5 + everyday example) and "Filipino/Taglish" (re-explain). Generate on demand, cache in DB. While one is made, ruled lines are written on one after another (`.rules` in `review.css`, paused off screen, blank rules under reduced motion).
- Key terms glossary (each one-line term's marker is drawn in once as it scrolls into view, `KeyTerms.jsx`)
- **Quick checks are grounded** (`server/src/pipeline/quick-checks.js`): the sections prompt asks only what the section's lesson text states ("why" / "how does X cause Y" only when the lesson states the reason), each check with an `evidence` quote. In code (`checkQuickCheck`) the quote must be in `raw_text` (like key terms: case, spacing, punctuation and line ends ignored, so neighbouring list lines can be quoted together; at most 40 words, cut where a sentence or clause ends by `trimQuote` in `pipeline/evidence.js`, so a reason is not cut off mid-phrase: a card's or key term's quote is cut the same way at 25 words), a "why" / "bakit" / "how does X cause…" question needs a quote that states a reason (because, since, so that, dahil, kasi, upang, para…), an answer that gives a reason needs a quote that gives one, the quote must say more than the question, and at least half of the answer's own words (not the question's) must be in the quote. A failing check is asked for again once, in one call for the whole lesson (label `the quick checks (second try)`), and dropped if it still fails, comes back unchanged or the call fails: a section may end with none, and the stage never fails for it. The quote is saved with the check in `check_questions` (`{ question, answer, evidence }`); the Filipino/Taglish version translates only the question and answer.
- **Quick checks in the AI review** (`server/src/services/check-review.js`, in the `quiz_review` stage after the cards): every section's checks with their quotes and the section text go to the strict reviewer, 12 sections per call (`quickCheckReviewPrompt`, label `the quick check review`; flags `not_in_lesson` (an invented reason, cause, effect or purpose between listed items, describing words or a new meaning), `not_answered` (the section's text doesn't answer it), `vague`; unknown flags dropped; a section left out of a reply that parsed counts as clean: the reviewer tends to list only the flagged ones). A flagged check is written again once (one call, label `the quick checks the review flagged`, grounded by `checkQuickCheck`; unchanged counts as failed), the sections that changed are reviewed again (label `the quick check review (after fixes)`), and what is still flagged, or could not be written again, is dropped from `check_questions` (kept in `sections.check_review.dropped` with why). Cached by a hash of the section text and its checks (`sections.check_review`, migration 014); a section whose checks change loses its cached Filipino/Taglish version (`filipino_version` holds translated copies of them). The stage is done only when both the cards and the checks are reviewed; admin's row carries `quiz_review.checks: { reviewed, pending, dropped }` (in quick checks; "N quick checks aren't checked by the AI reviewer yet." / "AI review: …; N quick checks dropped."), Review again resets both (and a lesson with quick checks but no quiz questions can be reviewed), and `npm run quiz:check` prints "Quick checks: N (M without a lesson quote); AI review: …" with the dropped ones. A failed review call saves nothing for its sections (the job is `failed` for admin).
- "View original text" toggle
- Resume where the student left off
- End card "What's next": study N due flashcards (~X min) → take quiz

### Flashcard (Anki-style)
- Row per lesson: name | Start | New / Learning / Due counts
- Study screen: front → tap to flip → Again / Hard / Good / Easy
- SM-2 scheduling. User-configurable: new cards/day (20), max reviews/day (200), learning steps (1m 10m).
- Defaults (code, each overridable by a `settings` row; see `server/src/flashcards/config.js`): graduating interval 1d, easy interval 4d, starting ease 2.50, easy bonus 1.30, hard interval 1.20, relearning step 10m, lapse new interval 0 (then min 1d), min interval 1d, max interval 36500d
- The study day starts at 04:00 Asia/Manila. Daily limits are one budget across all lessons ("All lessons" is the parent deck). Queue order: due (re)learning cards, due reviews, new cards (lesson order); learn ahead 20 min when nothing else is left.
- **Early-review guard** (`recordAnswer` in `server/src/flashcards/study.js`): an answer to a review-state card whose `due_at` is on or after the end of the current study day (the queue's own rule) is refused with 409 `not_due` (with `due_at`), so nothing is saved; learning and new cards are unaffected. The study screen never offers such a card; if it gets `not_due` (the card was answered in another tab) it quietly reloads the deck.
- **New-card limit guard** (same function): an answer to a new card when the participant has already answered `newPerDay` new cards this study day (`doneToday`, one budget across all lessons) is refused with 409 `new_limit` (with `new_per_day`), nothing saved. The queue never offers a new card beyond the limit, so the study screen is unchanged; on `new_limit` (another tab used up the day) it reloads the deck like `not_due`. Undo removes the answer from `doneToday`, so an undone new card can be answered again. Review answers (`maxReviews`) are not guarded.
- Intervals are fuzzed like Anki (±25/15/5%), from a seeded generator (seed = card id + reps), so the interval on a button is exactly what the card gets and tests are deterministic. The scheduler (`server/src/flashcards/scheduler.js`) is pure: it takes `now` and the config.
- Card generation is the pipeline's `flashcards` stage (also `POST /api/lessons/:id/flashcards/generate` for a lesson with no cards; the lesson stays ready while it runs). Term cards come from the grounded key terms; concept Q → A cards come from one AI call per chunk (the chunk's review sections as a guide). Every card has an `evidence` quote checked in code like key terms; answers over 40 words (prompt asks ≤ 25) are dropped; a concept card that gives its answer away is dropped (`cardLeaks` in `quiz/leaks.js`: **g** the front holds the back or 80% of its content words, **i** a yes/no or either/or question (English auxiliaries first, `o hindi`, `or not`, or `ba` in a question with no question word: "Ano ba…", "Bakit ba…" still ask what / why; a plain Filipino `o` is not one), **k** the back only restates the front (content-word overlap 0.8 or more, so "Bakit mahalaga…" → "Mahalaga … dahil …" is kept), **l** a concept card that asks by place in a list (`asksByPosition` in `quiz/leaks.js`: "Which aim is listed first?", "the second purpose", "item 3", "a second / third way", "another fourth reason", "the third method / type / kind", "the first learning objective", "the second topic / outcome / section", "2nd / 3rd" (one word may sit between the ordinal and the noun); "first impression", "a first draft" or "first step of the method" are not matched, and neither is "second step / stage", since a process lesson may teach its order; the same check refuses a quick check and a rewrite, and the quiz skips such a card); **m** a hint tail (`hintTail` in `quiz/leaks.js`: a concept card whose question ends in "regarding / related to / concerning / in terms of / with regard to / in relation to" plus words the answer repeats, "…the first objective regarding human populations?" -> "…human populations."; exact word forms, so the tail only points at the answer); after de-duplication, **j** a front that holds another card's answer). The prompt asks for no answer words in the question, no word that already means the answer, no yes/no or either/or questions, and an answer that says more than the question. Rule **h** (a term card's definition holds the term: both words of a one- or two-word term, as whole words or stems, or more than half of a longer one, so "cell" alone is not "Cell membrane") is information only, never dropped, counted as a leak or offered for Regenerate (`npm run quiz:check` prints it on an "Info:" line): the key-terms prompt forbids it and the quiz blanks the term; cards are de-duplicated against each other (term cards win). Card target: about one card per 50 words, at least 5, raised to the number of key terms plus list items (`targetCardCount`), at most `flashcards_max` (30); term cards take at most half of it, and less when list items need the room. **Every list item gets a card**: `listItems` reads the `- ` and numbered lines (before `Notes:`, at most 20 words each) and `uncoveredItems` the ones no card covers (its evidence holds the item, or the card's words hold 60% of the item's content words); while room is left, one more call (label `the flashcards for list items without a card`) asks for exactly one card per missing item, checked like the others and placed by where its evidence is in the lesson. A list item's card is never cut to fit the target: the cards that call adds get room beyond it (up to `flashcards_max`), and when cards must be cut, the first card asking about each item stays and the others go. **Nothing is made from learning objectives** (`isObjectiveBlock`, `withoutObjectives`, `onlyInObjectives` in `quiz/list-items.js`): a block is one when a short non-list heading line says "Learning Objectives", "Objectives", "Outline", "Agenda", "At / By the end of this lesson", "What we will learn" (before or after its list) or when 2 or more of its lines are "Students will be able to…" / "By the end of this lesson…". Those blocks are skipped by `listItems` and `listGroups`, and a card, term or quick check whose quote is found only inside them is dropped at generation (logged, `checkConceptCards`, `termCards`, `checkQuickCheck` with a `bodyKey`). Every prompt that makes content also carries `NO_OBJECTIVES` (`ai/prompts.js`), and flashcard prompts `ASK_BY_MEANING` (ask a list item by what it means, never by a "regarding + answer word" tail).
- Motion (`StudyScreen.jsx`, `DeckShuffle.jsx`, `FlipCard.jsx`, `lib/paper.js`): each time a deck starts, "Getting your deck out" with 3 or 4 random riffles (`shufflePlan`, about 0.6 s each, 1.8-2.4 s; tap, Enter, Space or Esc skips; a 450 ms fade under reduced motion; never "Shuffling": the queue order is fixed). The card sits on a deck (two `--card-edge` edges under it). The flip is a paper turn (3D rotateY with a fold shadow and a 4 px lift; cross-fade under reduced motion). After an answer, a ghost of the card goes back into the deck when its button comes back today (`comesBackToday`: minutes under a day) or onto a small done pile in the margin (its count written as an `.mnote`), and the pile squares up above the done card; undo plays it back out. Space flips, 1-4 answer, U / Ctrl+Z undo (multi-level within a session). "From the lesson: …" evidence under the answer. Done state says when the next card is due.

### Mock Quiz
- Row per lesson: name | Start | best finished score and number of attempts (`GET /api/quiz`). Lessons still preparing, without flashcards, or with only one card say why instead of Start.
- Questions come from the lesson's existing flashcards (no new grounding), built in code when a quiz starts (`server/src/quiz/build.js`, pure, seeded `random` in tests): up to 10 questions, one per card, cards picked at random; fewer if the lesson has fewer usable cards ("This lesson supports 6 questions"). A quiz needs at least 2 cards.
  - **Term card**: multiple choice "which term matches this definition?"; the 3 wrong options are other key terms of the same lesson (term cards, then `key_terms` without a card; plural-insensitive), no AI call. **Never a related term** (`server/src/quiz/related.js`, rule `r` in quiz:check): one whose words are a whole-word run inside the other's ("Self-Introduction" / "Written Self-Introduction") or that the AI review put in one family (`lessons.term_families`) is neither a wrong option nor a false statement for the other (both would be right). Families are for synonyms (or a broader and a narrower term whose names don't show it): `usableFamilies` drops a group that holds a term with its own kinds or only kinds of one thing (all ending in the same word), on save and on read, so siblings ("Written" / "Oral Self-Introduction") stay wrong options for each other. Fewer than 3 other terms: true / false against **another term card's definition only** (never a concept card's answer, which is plainly not a definition); with no other term card the card is not asked. A definition that holds its own term (or a form of it) is shown with the term blanked as `___` (`maskTerm`, which blanks every form `termInText` finds: a word of the term, a form of it (`sameForm`) or a shorter word it starts with ("observing" under "Observational", `inTerm`), never a longer word that holds one, so "databases" stays under "Archival Data" (lesson 32 card #742 was shown as "___ taken from existing records or ___."; Gemini audit 2026-10-18); the same match decides whether the blanked text still shows the term and rules d / e); the blanked text is checked again and a definition that still shows its term is neither asked nor used as another term's false statement; **a blanked definition is never another term's Yes/No false statement** (under "Does this describe Oral Self-Introduction?" the gap reads as a misprint and points at No), so **a term card whose definition is shown blanked gets no Yes/No form at all** (the gap only in the true statement points at it): it stays multiple choice, or is not asked; the stored `answer_text` and the card are unchanged.
  - **List-item card** (a concept card whose answer is exactly an item of a list in the lesson: a `- ` or numbered line on one slide or page with 3 or more such lines, before `Notes:`; case, spaces and a closing full stop ignored; `server/src/quiz/list-items.js`): the wrong options and false statements are the **other items of that list**, chosen in code like a term card's (the first 3 that pass the set checks, and only items of the answer's **shape** (`sameShape`: both names like "Authentic Tone" or both phrases / sentences, and the word counts within twice plus three of each other, judged on the list's own item), written with the answer's closing full stop or none (the AI writes an answer with one, a lesson's list line often has none, so the stop alone would mark the right option), no AI call; a line ending in ":" ("It reduces the risk of:") ends the list before it and starts a new list after it, so a sub-list is never a sibling of the main list; objective blocks are not lists; the wrong-answers stage skips these cards and the review's fix round has nothing to remake for them. Those items are other cards' answers too, which is accepted here (rule f's "another card's answer" is waived for them), as for term cards: they don't answer this question.
  - **Concept card**: multiple choice with 3 AI-made wrong answers. Without 3 clean ones: true / false, whose false statement is one of the card's own saved wrong answers that passes the checks or, with none saved, another concept card's answer on the same subject (sharing a content word with the question).
  - **Leak checks** (`server/src/quiz/leaks.js`, pure, English and Filipino/Taglish: stopwords of both, a light Filipino stemmer for the linker, prefixes, `-um-`/`-in-`, reduplication and suffixes, English plurals and -ing/-ed; each text is stemmed by its own language, and a short phrase whose language `language()` can't tell is compared under both stemmers, a match under either counting; the lesson's words for the off-topic check hold both stems of every word and are cached by the lesson text, `lessonWords`): nothing that gives its answer away is asked, and **nothing without text is saved, reviewed or shown** (`hasText` / `hasBlank` in `quiz/build.js`: no letter or digit once whitespace, invisible characters such as a zero-width space, and the `___` gap are taken away; applied to wrong options and false statements when the AI reply is parsed, saved and loaded, to the reviewer's items, to a term whose definition is only its own term, to a built question, and when an attempt starts). Rules: **a** the question holds the answer or 80% of its content words (a one-word answer only as a whole word or stem: "Cell" is not in "excellent", "Data" not in "database"; a form of a word is the word: `sameForm`, "professional" / "professionalism", "create" / "creates" / "creation", a shared base of at least 5 letters plus a common ending, or of at least 4 for the plain inflections `-s -es -d -ed -ing`: "formed" / "form", "reviewed" / "review"; "state" / "statement", "form" / "formal" and "data" / "database" stay apart; also in rules b and h; a 2-word answer with one word echoed, like "Form hypothesis" under "What is formed…", is still under rule g's 80% and is not flagged); **b** two or more words of the question that only the right option repeats, as the same word or stem ("data" is not "database"), leaving out the question's topic (its word the lesson uses most, such as `wika` or "plants"), so one echoed word never flags; **c** the right option stands out (length outside 0.6-1.6x and more than 4 words apart, the only full sentence, every wrong option opens with the same 2 words, or tone: the wrong ones are negative or reversed beside a positive right answer, or the right answer is the only negative one. Negatives are whole words: `hindi`, `wala`, `not`, `never`, English reversing verbs in their inflected forms (`prevent(s/ed/ing)`, `hide(s)`, `hiding`, `remove`, `harm(ful)`...; not `hidden`, `harmony`, `blockchain`, nor `reduce` / `decrease`, which only describe an amount), Filipino reversing stems compared exactly (`pigil`, `tigil`, `bura`, `hadlang`, `wala`...; not `burador`), and `mahirapan`, `alisin`, `itago` only in those verb forms (`paghihirap`, `pag-alis`, `nakatago` are topic words); `bawas` no longer counts; "No. 7" / "(no.)" is the number sign); **d** a term question's definition holds the term; **e** a Yes/No false statement that is false from its wording (negative, another language, another kind of card's answer, another subject, another concept card's answer when it is a saved wrong answer) or that is the right answer's own words (reworded, so maybe true, or reversed); a term question's false statements (other term cards' definitions) also go through it, and never name the asked term; **f** wrong options that are near-duplicates of each other (content-word overlap 0.7 or more), the right answer's own words (a second right answer, or a swapped / reversed copy), another concept card's answer (it plainly answers that other question, so a student matches it away), in another language, or about nothing in the lesson; **and, for a concept card's own saved wrong answers (not list siblings, not another card's answer, not Filipino, not two enumerations of 4 or more items), an option sharing `REWORDED` = 0.36 of its content words with the right answer, which is the same claim reworded (a second right answer): this is also rule e for such an option used as a false statement.** The 0.36 threshold was measured before it was kept (lessons 25-31 plus three fresh runs of Self-Introductions, Nature of Inquiry and RSCH2120 that the threshold was not tuned on): it dropped options only in lesson 27 (44 of 107, every one a reworded right answer: "used to promote a local service or event" for "used to advertise a product, service, or event"), nothing in the fresh runs, and one legitimate option in lesson 28 (the same list of five with one item swapped), which the enumeration exemption now keeps; the Filipino exemption exists because the stemmer cuts "nagkaroon" to "roon", so two options in one sentence frame looked reworded. `quizCandidates` in `build.js` keeps only clean forms per card (multiple choice first, then Yes/No, else the card is skipped), so a lesson that can't fill 10 clean questions gets fewer ("This lesson supports N questions"); `usableCount` (the Mock Quiz tab's number) uses the same filter with the saved wrong answers and the lesson text. These are word checks: a question whose *meaning* gives the answer ("Why is language called dynamic?" -> "it changes"), a wrong option reversed in meaning without a negative word, or a synonym of the right answer ("pagbabahagi" for "share") is left to the prompts and the admin flag.
  - About 3 in 10 questions are true / false (choices `True` / `False`) for variety even when every card could be multiple choice. Multiple-choice options are shuffled silently. **Trailing punctuation never tells options apart** (`normalizeTrailing` in `server/src/quiz/build.js`, found when a Claude-written lesson had "Hypotheses." as the only option ending in a full stop, 11 of its 23 multiple-choice questions, and the code checks did not see it): of the texts shown together (a multiple-choice question's four options; for Yes/No the statement, its sibling false statements and the real answer), when some end in a full stop, a colon or an ellipsis (`…` or `...`) and others don't, that mark is taken off every text that has it, each mark on its own, so a lone ellipsis or colon goes too. Nothing is changed in the card, `quiz_distractors` or the reviews: only the built question is, which `quiz_answers` stores as shown, like a blanked term (`answer_text` follows, so `choices[answer_index]` is still `answer_text` and a true statement is still its `answer_text`; the codebook says so). Left alone when every text agrees, and when taking a mark off would make two different texts equal ("Errors." and "Errors") or leave one with no text. An inner stop ("e.g. surveys") stays. Tests: `server/test/quiz-trailing.test.js` (lesson 33's case). Not retroactive: an attempt started earlier keeps the text it was made with.
- **Wrong answers** (`server/src/quiz/distractors.js`): made as the last step of lesson processing (the pipeline's `quiz_options` stage, after flashcards; the lesson stays `processing` until it ends, so students never wait on the AI when starting a quiz). The AI is asked (existing adapter, rate limiter, zod, one JSON retry) for 3 wrong answers per concept card, in batches of at most 15 cards so each call stays under the 25 s timeout; batches run up to the provider's concurrency. The prompt gets each card's question, answer, evidence quote, word count and language, uses only that lesson content, explains `Notes:`, and asks for wrong answers that directly answer **this** question and are the same kind of thing it asks for (a condition for "Kailan…", a list of the same category for "Anong uri…"), never another card's answer, on the question's subject, similar in length and style to the correct one, **in the same tone and polarity** (no negations, opposites or "hides / prevents / limits" versions; it no longer asks to "reverse a relationship", which made the right answer the only positive option), echoing the question's words when the right answer does. In code, wrong answers that match the correct answer or each other (case-insensitive, trimmed), run over 40 words, or break rule c (tone, length) or f (language, off-topic, the right answer's own words, another card's answer) are dropped, and the 3 kept must pass b / c / f as a set (`pickWrongSet`). A card left without a clean set gets **one** follow-up call (label `the quiz answer options (second try)`) listing the kept answers and the rejected ones with why; whatever is clean then is saved (fewer than 3: the card is asked as Yes/No), and a set still not clean after that call is **settled** (`quiz_distractors.settled = 1`, migration 010): no remake or lesson retry asks the AI for it again (a failed follow-up call does not settle it; regenerating the card deletes the row). Saved in `quiz_distractors` and reused; a batch that fails is not saved. **Failure of this stage does not fail the lesson:** the job records `quiz_options` / `failed` with the message, the lesson is `ready`, and admin gets a retry button (`POST /api/lessons/:id/quiz-options`, also used to fill in lessons made before the stage existed and to remake saved sets that give the answer away; only those cards are asked for). No wrong answers are made for a card that can never be multiple choice (its question gives the answer away, rule a or k). A set is saved only if the card's question and answer are still the ones it was made for (a card regenerated during the call is asked for again). The stage and the retry use `includeFailing` (`cardsNeedingDistractors`): cards with no saved row plus cards whose saved set the quiz can't use (not cards whose own question gives the answer away, nor settled sets), so the stage converges. Admin's list (`GET /api/lessons?counts=1`) rows carry `quiz_options.missing` (none saved) and `quiz_options.weak` (saved but leaking, not settled, and the card's own question doesn't give the answer: what a remake can still fix; the admin row then says "N quiz questions are skipped or changed to keep answers hidden." with **Remake quiz answers**). **Fallback:** starting a quiz still calls `ensureDistractors` for any card without them (never for a saved set that leaks: the builder just leaves it out), so the quiz starts either way (with a notice and true / false questions if that fails too). `ensureDistractors` is shared per lesson: the stage, a retry and quiz starts that overlap wait for one AI call (an `includeFailing` call that finds a missing-only run waits for it, then runs its own).
- **AI exam review** (`server/src/services/quiz-review.js`, the pipeline's `quiz_review` stage after `quiz_options`; Default model only): every card the quiz can ask is shown to a strict reviewer with all the forms it can be asked in (question, right answer, the right answer as a Yes/No statement, every wrong option and false statement that passed the code checks, each marked `mc` / `yes_no` / `both`; the prompt says another item or term of the lesson that does not answer the question is a good wrong option, `off_topic` means the lesson doesn't cover it at all, and an option that only rewords the right answer is `two_correct`; `two_correct` is judged by meaning, not words, with three examples on made-up topics (two kinds that both fit a definition, a reworded benefit, a reworded drawback) so the lessons we grade stay unseen; in code an `off_topic` flag is ignored when the option's text is found in `raw_text` (`comparable`, case/spacing/punctuation ignored), and the prompt says so too) and the lesson (all of it under 16K characters, else the blocks around the batch's quotes), 12 cards per call (`quizReviewPrompt`). Flags (`server/src/quiz/review-flags.js`): card `card_reveals` | `not_in_lesson` | `vague` | `off_topic` (made from the lesson's learning objectives / outline / agenda: written again, else left out; the quick-check review has the same flag); set `giveaway` (also when the right answer rules the others out by itself: "relevant" beside "all details" / "everything"; one echoed word of the question is allowed, rule b); true statement `giveaway` | `not_in_lesson`; option `two_correct` | `reversed` | `off_topic` | `giveaway` (a caricature or extreme: "all details", "everything", "always", "as long as possible"); card `not_in_lesson` also covers an invented cause or effect between listed items and a rewording with a new meaning; unknown flags are dropped; an item the reviewer leaves out of a reply that parsed counts as clean (saved with no flags, like a section in the quick-check review), the prompt asks for one entry for every item, and a reply that matches none of the batch's cards fails the batch (nothing saved, the cards stay pending) so an empty reply cannot mark everything clean. A wrong option or false statement that is the opposite of the right answer with no negative word ("Creates anxiety" for "Builds confidence") is flagged `reversed`; the wrong-answer prompt forbids it. The first call also groups the key terms into families. **One fix round**: a concept card's flagged options (or its whole set, for a set giveaway) are made again in one call per batch (`remakeFlagged`, label `the quiz answer options (after review)`, the reviewer's reasons given as the rejected answers; still not clean: settled); flagged cards (and an answer `not_in_lesson`) are written again in one call per batch (`regenerateCardsPrompt`, label `the flashcards the quiz review flagged`, each checked by `checkNewCard` like admin's Regenerate and saved in place, its wrong answers deleted and made again; **never once a participant other than P00 has records**: the card is then only left out). A rewrite that keeps every content word of the old card ("It is presented…" -> "This is presented…", `unchangedRewrite`) counts as failed: not saved, the card stays left out, and it spends no round-2 call. Round 2 (label `the quiz review (after fixes)`) reviews **every** card whose review went out of date in the fix round, not only the ones made again: a term card's new definition is another term's false statement, a concept card's new answer can be another card's option, so nothing is left "not reviewed yet"; whatever is still flagged is left out: a flagged card is not asked, a flagged option or false statement not shown, a flagged set not asked as multiple choice, a flagged true statement not as Yes/No. A term card's flagged options (other key terms) and a giveaway true statement are left out without a remake. Saved per card in `quiz_reviews` (migration 013) with a hash of the card's text and of everything shown, so it is cached: a card is reviewed again only when what the quiz shows changes (a regenerated card's old verdict no longer applies). A failed review leaves the lesson ready (the job is `failed` for admin); an unreviewed card is asked as the code checks allow. Admin's row (`quiz_review: { reviewed, flagged, pending, checks, status, error }`) says "AI review: N of M cards flagged." with **Review again** (`POST /api/admin/lessons/:id/quiz-review`: with cards not reviewed yet or changed since, the row says "N quiz questions aren't checked by the AI reviewer yet." and the button **Review quiz** reviews only those; with none, it clears every card's hash so all are reviewed again, with one more fix round), and `npm run quiz:check` prints the review with the flagged cards and why.
- Untimed. Time per question (`time_ms`, capped at 1 h) and total time (`duration_ms`) are recorded. Quiz results never touch flashcard scheduling or `flashcard_reviews`.
- Screen (`#/quiz/:lessonId`): "Getting your quiz ready" (after 2.5 s: "The AI is thinking up answer options…"), then the test sheet is handed out (slides up 32 px and fades in, 420 ms; a tap, Enter, Space or Esc skips; a fade under reduced motion), then one question at a time with no wait between them (no exit animation: the next question is the only one on the sheet), the progress as answer-sheet bubbles (`AnswerSheet`, `bubbleStates` in `lib/quiz.js`: answered filled, current a ring, neutral only; `role="progressbar"`). After an answer is saved it is marked in pen (`Pen.jsx`): a loop drawn round the chosen option's number, a tick on the right option, a strike through a wrong chosen one (one-line options only); a tap finishes them and Next never waits. The results' score is circled like a grade. After each answer: correct / not quite, the right answer and the card's "From the lesson: …" evidence; Next sits in the pinned action bar. Keys: 1-4 answer (1-2 on true / false), Enter next. A true / false question is **shown as Yes / No** (`yesNoAsk` / `yesNo` in `client/src/lib/quiz.js`; kicker "Yes or no?"): the thing judged is the big heading, a smaller line says what it is judged against, and a short question sits above the buttons Yes / No (`yesNoAsk` returns `{ heading, label, context, ask }`; the heading is the focus target, the options group is labelled by heading and question, and `questionText` reads them in that order): a term card shows the **term** as the heading, "Suggested meaning:" + the definition, then "Does this match?"; a concept card shows the **suggested answer** as the heading, "For:" + the card's question, then "Is this the answer?". The first letter of an option, of the suggested answer and of the shown definition gets a capital for display only (`capitalFirst`; "iPhone" / "pH" are left alone; the stored text is never changed). The results list ("Missed questions": the question, "Your answer", "Right answer" as Yes, or No plus the real answer) uses the same wording. It is display only: `choices`, `chosen_answer`, `right_answer` and the export stay True / False, and the codebook says so. Focus moves to each new question, then to Next (described by the feedback), then to the results heading.
- Results: score, percent, time, comparison with the best earlier score, the missed questions (your answer, right answer, evidence), **Retake** (same questions, new question order and option order, shuffle again) and **Back to lesson**. The Flashcards done card's main action is "Take the mock quiz".
- Tables (migration 007):
  - `quiz_reviews` (flashcard_id PK → flashcards ON DELETE CASCADE, lesson_id, card_hash, item_hash, card_flags / set_flags / true_flags JSON `[{ flag, why }]`, option_flags JSON `{ option text: [{ flag, why }] }`, round 1 | 2, made_by, reviewed_at; migration 013, which also adds `lessons.term_families`): the AI exam review, shared like the cards, never exported. `quizBuildOptions` (`server/src/quiz/options.js`) reads it (and the families) for the quiz routes, admin's leak report and quiz:check, and works without them on an older database.

### Stats
- Per participant (`GET /api/stats`, `server/src/stats/participant.js`); `StatsScreen.jsx` and `StatsView.jsx` are lazy-loaded. Written as a page of notes: no cards or tiles.
- Study time this week: a sentence with the total (highlighted), the three parts as a legend line, then one ruled line per day Mon–Sun (the day in the margin, a bar in the activity colours scaled to the busiest day, inked in from the left once per Stats open (scaleX, 40 ms apart, a tap finishes it), the time written at the end; segments come from `daySegments` in `lib/stats.js`, which leaves out a zero, so no stray "0" is rendered), "Most active day", and a "Show as a table" view.

- Quiz scores: first and best finished score per lesson (abandoned attempts not counted): the best in the margin, the lesson title as an `<h3>`, a thin track per score.
- Chart colours are the `--series-reading` (navy / pale blue; AMA's is #3548a8, apart from its accent #2A367D, and inside the dataviz lightness band), `--series-flashcards` (orange) and `--series-quiz` (teal) tokens in `tokens.css`, spread in lightness for colour-blind readers, and the quiz is also striped (`.swatch--quiz`, `data-activity="quiz"` in `stats.css`), so no series relies on colour alone, for study time; every value is also written out (legend, day lines, table). The quiz-score bars do not reuse those (they would mean two things on one screen): Best is `--accent` (`--score-best`: `--ink` in the AMA themes, so the line never reuses a series colour), First try is `--ink-2`, and a lesson with one finished quiz shows a single "Score" bar.
- Flashcard done card recap: cards studied this sitting, active time, % Good/Easy (undone answers removed; `sessionRecap` in `lib/flashcards.js`).

## Data Model
- `lessons` (id, title, filename, raw_text, word_count, status, error, created_at, source_kind, source_numbers JSON, source_total, origin `admin`|`student`, owner_participant_id → participants ON DELETE SET NULL, shared_at, error_kind `content`|`ai`|`other`, processed_thinking `off`|`high`|`mixed` (no longer written), thinking_level `minimal`|`low`|`medium`|`high`|`mixed`, made_by `gemini`|`claude-haiku`|`mixed`) (the four after source_total: migration 012; `processed_thinking`: migration 015; `thinking_level`: migration 016; `made_by`: migration 017)
  - `origin = 'student'` is a student's upload: private to `owner_participant_id` until `shared_at` is set by admin. See Student uploads.
  - `source_numbers[k]` is the real slide / page number (Word: paragraph number) of the k-th block of `raw_text`, `source_kind` is `slide` | `page` | `paragraph` and `source_total` the real count. A slide or page with no text has no block, so a block's place in `raw_text` is not its slide number. NULL on lessons uploaded before migration 005.
- `jobs` (id, lesson_id, stage, status, error, updated_at)
- `sections` (id, lesson_id, position, title, content, simple_version, filipino_version, check_questions JSON `[{ question, answer, evidence }]` (no `evidence` on lessons made before it), sources JSON, check_review JSON `{ hash, round, flags, dropped, made_by, reviewed_at }` (migration 014, the quick-check review))
  - `sources` is the sorted list of slide / page numbers the section was written from. The sections prompt labels each block (`[Slide 3]`) and asks the model for `sources`; in code each number must be a whole number within `source_total` and the number of a block that was in that call's chunk, anything else is dropped and logged, and if nothing is left it is NULL. Original text shows exactly those slides / pages; NULL (older lessons) falls back to a vocabulary match in the client, labelled approximate.
  - `simple_version` stores JSON `{ text, example }`, `filipino_version` stores JSON `{ title, content, check_questions }`; both are made on demand and cached here, the original `content` is never changed.
  - `review_progress.last_section` and `completed_sections` are 0-based indices into the lesson's sections in order.
- `key_points` (id, lesson_id, position, text)
- `key_terms` (id, lesson_id, term, definition, evidence)
- `participants` (id, code UNIQUE, created_at) (migration 008; `P00` made by the migration). Deleting a row cascades to every per-participant table.
- `review_progress` (participant_id, lesson_id, last_section, completed_sections JSON, updated_at), PK (participant_id, lesson_id)
- `flashcards` (id, lesson_id, front, back, state, ease, interval, due_at, reps, lapses, step, kind, evidence, position)
  - `kind` `term` | `concept`; `position` is the new-card order within the lesson. Since migration 008 the scheduling columns here are no longer read: the schedule is per participant in `flashcard_progress`.
- `flashcard_progress` (participant_id, flashcard_id, state, step, ease, interval, due_at, reps, lapses), PK (participant_id, flashcard_id)
  - state 0 new / 1 learning / 2 review / 3 relearning; `interval` in days. No row = the card is new for that participant.

  - one row per answer: rating = button (1 Again … 4 Easy), `state` before the answer (daily limits count it), `ease` after, intervals in days (a learning step is a fraction of a day), `snapshot` = the participant's scheduling fields before the answer plus `existed` (for undo: a card that had no progress row gets none again; undo deletes the row).

- `quiz_attempts` (id, participant_id, lesson_id, score, total, answers JSON, taken_at, + migration 007 columns)
